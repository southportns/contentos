# P0.4.5 — Draft Version Lineage

## 1. Objective

在 P0.4.3 Draft Version Restore 和 P0.4.4 Draft Version Integrity 的基础上，为 Draft 建立明确的版本来源关系。

核心目标：**系统能够知道一个 Draft 是从哪个 Draft 版本创建而来的。**

## 2. Current Problem

P0.4.3 Restore 创建了 `createRestoredDraft` 方法，但数据库没有记录新版本与源版本之间的关系：

```
Restore v2 → Create v5
```

但数据库不知道 `v5.parent = v2`，版本历史是扁平的列表，无法回答"这个版本从哪里来"。

## 3. Schema Design

为 Draft 模型添加 `parentDraftId` 字段和自引用关系：

```prisma
model Draft {
  id            String   @id @default(cuid())
  topicId       String
  version       Int      @default(1)
  parentDraftId String?                // ← P0.4.5 新增

  title         String?
  content       String
  outline       Json?
  status        String   @default("DRAFT")
  wordCount     Int?
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  topic               Topic                @relation(...)
  parentDraft         Draft?               @relation("DraftLineage", fields: [parentDraftId], references: [id], onDelete: SetNull)
  childDrafts         Draft[]              @relation("DraftLineage")
  evaluation          Evaluation?
  humanization        Humanization?
  strategyEvaluation  StrategyEvaluation?

  @@index([topicId])
  @@index([parentDraftId])   // ← P0.4.5 新增
  @@unique([topicId, version])
}
```

### 设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 删除策略 | `onDelete: SetNull` | 父版本被删除时，子版本保留（历史版本不能级联删除） |
| 可空性 | `parentDraftId: String?` | 初始 Draft 没有父版本 |
| 索引 | `@@index([parentDraftId])` | 加速 lineage 查询 |
| 关系名 | `"DraftLineage"` | 避免与 topic 关系冲突 |

## 4. Migration

**文件**: `prisma/migrations/20260922150000_add_draft_lineage/migration.sql`

```sql
-- P0.4.5 — Add parentDraftId self relation for Draft lineage tracking
ALTER TABLE "Draft" ADD COLUMN "parentDraftId" TEXT;
CREATE INDEX "Draft_parentDraftId_idx" ON "Draft"("parentDraftId");
```

注：由于项目存在 migration drift（预存在问题），手动创建 migration SQL 而非使用 `prisma migrate dev`。

## 5. Lineage Rules

| 规则 | 实现 | 测试 |
|------|------|------|
| 初始版本 parentDraftId = null | 创建新 Draft 时不设置 parentDraftId | Test A |
| Restore 设置 parentDraftId = source.id | `createRestoredDraft` 中 `parentDraftId: sourceDraft.id` | Test B, C, D |
| 跨 Topic 拒绝 | API 设计上不可能（topicId 来自 sourceDraft） | Test E |
| self-parent 保护 | API 设计上不可能（新 ID ≠ source ID） | Test F |
| SetNull 行为 | `onDelete: SetNull` 保证子版本保留 | Test G |
| 历史不可覆盖 | Restore 只创建新 Draft，不修改旧版本 | Test H |

## 6. Restore Integration

**文件**: `src/lib/repositories/topic-repository.ts`

修改 `createRestoredDraft` 方法中的 `tx.draft.create` 调用：

```typescript
return tx.draft.create({
  data: {
    topicId: sourceDraft.topicId,
    version: nextVersion,
    parentDraftId: sourceDraft.id,  // ← P0.4.5 新增
    title: sourceDraft.title,
    content: sourceDraft.content,
    outline: sourceDraft.outline,
    status: 'DRAFT',
    wordCount: sourceDraft.content.length,
  },
})
```

## 7. UI Changes

**文件**: `src/components/projects/draft-version-history.tsx`

### 7.1 版本列表 — 来源指示器

在版本列表中，如果 Draft 有父版本，显示来源：

```tsx
{draft.parentDraftId && versionById.has(draft.parentDraftId) && (
  <div className="text-xs text-muted-foreground mt-0.5">
    ↳ 由 v{versionById.get(draft.parentDraftId)} 创建
  </div>
)}
```

效果：
```
v5   DRAFT
     由 v2 恢复
```

### 7.2 详情面板 — 版本来源

在详情面板中显示版本来源信息：

```tsx
<div className="text-xs text-muted-foreground">
  {selectedDraft.parentDraftId && versionById.has(selectedDraft.parentDraftId) ? (
    <span>版本来源：由 v{versionById.get(selectedDraft.parentDraftId)} 创建</span>
  ) : (
    <span>初始版本</span>
  )}
</div>
```

效果：
- `parentDraftId = null` → 显示 "初始版本"
- `parentDraftId = v2.id` → 显示 "版本来源：由 v2 创建"

## 13. Limitations

1. **No DAG visualization**: P0.4.5 只记录 lineage 数据，不做图形化展示
2. **No normal creation lineage**: 普通 Writing Workflow 的 Draft 创建不记录 parentDraftId（保持 scope 最小化）
3. **No cross-topic validation in code**: 跨 Topic 防护是结构性保证（API 设计决定），非显式校验
4. **Migration drift**: 项目存在 migration drift，使用手动 SQL migration
