# P0.4.9 — Active Draft Cross-Tab Sync

## 目标

实现同一浏览器内、同一用户、同一 Topic 的多个标签页之间，实时同步 Active Draft 状态。

## 背景与问题

当用户在多个浏览器标签页中编辑同一个 Topic 的不同 Draft 版本时，一个标签页更改 Active Draft 到其他版本时，其他标签页不会自动感知此变更，导致：

1. UI 上仍显示旧的 Active Draft
2. 用户继续编辑时可能基于错误的版本操作
3. 数据不一致风险

## 范围

- ✅ 使用 BroadcastChannel API 实现标签页通知
- ✅ 数据库为最终事实来源
- ✅ 仅通知机制，数据通过 router.refresh() 从服务器获取
- ❌ 不修改历史 migration
- ❌ 不新增 Prisma 字段
- ❌ 不使用 SharedWorker / WebSocket / SSE

## 技术选型

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| BroadcastChannel | 原生 API，浏览器内实时，轻量 | 仅限同源标签页 | ✅ |
| SharedWorker | 持久化，可协调 | 实现复杂，调试难 | ❌ |
| WebSocket/SSE | 全浏览器支持 | 服务端依赖，架构重 | ❌ |
| localStorage 事件 | 跨浏览器兼容 | 不同源标签页不支持，延迟 | ❌ |

## 消息结构

```typescript
interface ActiveDraftChangeMessage {
  type: 'ACTIVE_DRAFT_CHANGED'
  topicId: string
  draftId: string
  sourceId: string   // 发送方唯一标识
  timestamp: number  // 发送时间戳
}
```

## 安全与降级

1. SSR 安全：BroadcastChannel 仅在 useEffect 中创建
2. 旧浏览器：typeof BroadcastChannel === 'undefined' 时静默降级
3. 内存泄漏：useEffect 清理函数中 close() channel
4. 错误隔离：BroadcastChannel 错误不影响主流程

## 消息过滤策略

使用 `shouldAcceptActiveDraftMessage` 函数进行多维度过滤：

1. **wrong-topic**: 不同 Topic，拒绝
2. **self-message**: 本机发送，拒绝（sourceId 匹配）
3. **stale**: 时间戳早于最后已处理消息，拒绝
4. **no-change**: draftId 与当前一致，拒绝
5. **valid**: 接受并回调
