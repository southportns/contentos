# P0.4.7 — Draft Version Lineage Explorer

## 1. Objective

Transform the existing Draft Version History from a flat version list with text-based lineage hints into an interactive Lineage Explorer that allows users to:

- Visualize the ancestry chain of any version
- Navigate to parent versions with one click
- Discover and navigate to child versions (branches)
- Understand branch points in version history

## 2. Current Problem

Prior to P0.4.7, the UI could only display:

```
恢复版本 · 由 v2 创建
```

This text-based approach fails to answer key questions:
- "What other versions came from v2?"
- "How did we get to v4? What's the full path?"
- "Is this version a branching point?"

Users had no way to navigate the version tree interactively.

## 3. Existing Lineage Model

P0.4.5 already established the data model:

- `parentDraftId` — self-referencing foreign key on Draft
- `changeType` — INITIAL | RESTORE | MANUAL_EDIT | REGENERATE | REFINE | HUMANIZATION | OTHER
- `changeReason` — optional human-readable reason

No new database fields or migrations are needed for P0.4.7.

## 4. Utility Design

### 4.1 `getParentDraft<T>(draft, drafts): T | null`

- Returns `null` if `parentDraftId` is falsy
- Returns `null` if parent not found (safe degradation, no throw)
- Returns the parent draft object if found

### 4.2 `getChildDrafts<T>(draft, drafts): T[]`

- Filters all drafts where `parentDraftId === draft.id`
- Sorts result by `version` ascending
- Returns empty array if no children

### 4.3 `getLineageChain<T>(draft, drafts): T[]`

- Walks up the parent chain from current draft to earliest ancestor
- Returns ordered array: `[ancestor, ..., parent, current]`
- Cycle protection via `Set<string>` of visited IDs
- Missing parent causes graceful termination (returns what was found)

**Cycle Protection:**
```typescript
const visited = new Set<string>()
// ... before adding parent to chain:
if (visited.has(current.parentDraftId)) break
```

## 6. Parent Navigation

- Clicking the parent link (`← 来源版本：v2`) calls `setSelectedVersion(parentDraft.version)`
- Detail Panel immediately updates to show parent's content
- No page navigation (`router.push` is NOT used)
- If `parentDraftId` references a deleted/missing draft, shows `来源版本已不存在`

## 7. Child Navigation

- Children displayed as buttons: `v5 · 精修`
- Clicking a child calls `setSelectedVersion(child.version)`
- Detail Panel immediately updates
- Empty state shows: `暂无派生版本`

## 8. Lineage Chain

The visual chain shows the full ancestry:

- v1 → v2 → v4 (current)

Each ancestor is clickable for direct navigation. The chain only appears when `lineageChain.length > 1`.

## 9. Cycle Protection

The `getLineageChain` function uses a `visited` Set to prevent infinite loops:

1. Starting draft is added to `visited`
2. Before adding a parent, check if its ID is already in `visited`
3. If yes, break the loop immediately
4. This handles both 2-node cycles (v1 ↔ v2) and longer cycles (v1 → v2 → v3 → v1)

## 10. Missing Parent Handling

All three utility functions handle missing parents gracefully:

| Scenario | `getParentDraft` | `getChildDrafts` | `getLineageChain` |
|----------|------------------|------------------|-------------------|
| `parentDraftId = null` | Returns `null` | Returns `[]` | Returns `[current]` |
| Parent deleted | Returns `null` | N/A (filtered out) | Returns chain up to gap |
| Cycle detected | N/A | N/A | Breaks loop, returns what was found |

UI shows `来源版本已不存在` for dangling parent references.

## 13. Known Limitations

1. **No DAG visualization library** — Lineage is shown as a vertical chain, not a full tree diagram
2. **Direct children only** — Grandchildren are not shown in the Lineage Explorer
3. **Single-parent assumption** — Each draft has at most one parent (enforced by `parentDraftId`)
4. **Client-side only** — All lineage computation happens in the browser using already-loaded drafts
