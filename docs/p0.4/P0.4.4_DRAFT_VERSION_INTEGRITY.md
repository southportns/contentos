# P0.4.4 — Draft Version Integrity Hardening

## 1. Objective

在 P0.4.3 Draft Version Restore 基础上，对 Draft Version 系统进行数据库级完整性加固，确保同一个 Topic 下 Version 永远不能重复。

## 2. Problem

P0.4.3 的 `createRestoredDraft` 使用 `prisma.$transaction` 并在事务内读取 max version 后创建新 Draft。但 Prisma Schema 的 `Draft` 模型缺少数据库层面的唯一约束：

```prisma
// 之前只有 index，没有 unique
@@index([topicId])
```

这意味着：
- 并发操作可能产生重复的 `(topicId, version)` 组合
- 应用层逻辑无法 100% 保证唯一性
- 没有冲突恢复机制

## 3. Solution

采用多层防御策略：

```
Application Logic (max version re-read)
        +
Transaction (atomicity)
+
Database Unique Constraint (@@unique)
+
Conflict Handling (P2002 detection)
+
Retry Mechanism (max 3 attempts)
+
Error Mapping (DRAFT_VERSION_CONFLICT)
```

核心原则：**Application Logic Prevents Conflicts, Database Constraint Guarantees Integrity.**

## 4. Schema Change

**文件**: `prisma/schema.prisma`

为 `Draft` 模型添加联合唯一约束：

```prisma
model Draft {
  id        String   @id @default(cuid())
  topicId   String
  version   Int      @default(1)
  // ... other fields ...

  @@index([topicId])
  @@unique([topicId, version])  // ← P0.4.4 新增
}
```

效果：
- `Topic A + v1` ✅ / `Topic A + v2` ✅ / `Topic A + v3` ✅
- `Topic A + v2` + `Topic A + v2` → 数据库拒绝 (P2002)
- `Topic A + v1` + `Topic B + v1` → 允许（不同 Topic）

## 5. Migration

**文件**: `prisma/migrations/20260922132000_add_draft_topic_version_unique/migration.sql`

```sql
-- P0.4.4 — Add unique constraint on Draft(topicId, version)
CREATE UNIQUE INDEX "Draft_topicId_version_key" ON "Draft"("topicId", "version");
```

说明：
- 使用 `CREATE UNIQUE INDEX` 实现 SQLite 的唯一约束
- 不修改已有 Draft 数据
- 不删除任何历史版本
- 不修改 version 值

注：由于项目存在 migration drift（预存在问题），手动创建 migration SQL 而非使用 `prisma migrate dev`。

## 6. Concurrency Strategy

**文件**: `src/lib/repositories/topic-repository.ts`

### 6.1 架构变更

P0.4.3 将整个操作（包括 source draft 读取）放在事务内。P0.4.4 优化为：

```
Step 1 (事务外): 读取 source draft + 校验 ownership
    ↓
Step 2 (事务内): 读取 max version + 创建新 Draft
    ↓
冲突时: 重试（重新执行 Step 2）
```

### 6.2 为什么 source draft 读取在事务外？

- Source draft 读取是只读操作，不会引发冲突
- 减少事务持有时间，降低死锁风险
- 冲突只可能发生在 version 创建阶段

### 6.3 事务内操作

```typescript
const newDraft = await prisma.$transaction(async (tx) => {
  // 每次事务内重新读取 max version（获取最新值）
  const maxVersionDraft = await tx.draft.findFirst({
    where: { topicId: sourceDraft.topicId },
    orderBy: { version: 'desc' },
    select: { version: true },
  })
  const nextVersion = (maxVersionDraft?.version ?? 0) + 1

  return tx.draft.create({
    data: {
      topicId: sourceDraft.topicId,
      version: nextVersion,
      // ... content fields
    },
  })
})
```

## 7. Retry Strategy

**最大重试次数**: 3

```
Attempt 1 → P2002 conflict → re-read max version → retry
Attempt 2 → P2002 conflict → re-read max version → retry
Attempt 3 → P2002 conflict → throw DRAFT_VERSION_CONFLICT
```

### 关键设计决策：

1. **只重试 P2002 错误**：其他错误（如 DB_WRITE_FAILED）立即抛出，不重试
2. **每次重试重新读取 max version**：确保使用最新的 version 值
3. **有限重试**：最多 3 次，防止无限循环
4. **非 P2002 错误立即抛出**：避免掩盖真正的系统错误

## 8. Error Mapping

**文件**: `src/lib/services/server-actions.ts`

```typescript
case 'DRAFT_VERSION_CONFLICT':
  // P0.4.4 — Version creation conflict after max retries
  return { success: false, error: '版本创建冲突，请重试' }
```

### 错误映射规则：

| 内部错误 | 用户可见消息 | 暴露细节 |
|---------|------------|----------|
| SOURCE_DRAFT_NOT_FOUND | 该版本不存在或已不可用 | ❌ |
| TOPIC_NOT_FOUND | 项目上下文不存在 | ❌ |
| OWNERSHIP_DENIED | 无权操作此版本 | ❌ |
| DRAFT_VERSION_CONFLICT | 版本创建冲突，请重试 | ❌ |
| 其他 | 恢复失败，请稍后重试 | ❌ |

**绝不暴露**: Prisma, SQL, P2002, database constraint, stack trace
