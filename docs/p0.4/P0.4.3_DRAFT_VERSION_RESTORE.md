# P0.4.3 — Draft Version Restore

## 1. Objective

P0.4.1 解决了"我有哪些版本？"，P0.4.2 解决了"两个版本之间到底差在哪？"。本阶段解决：

**"基于历史版本创建新草稿，同时保证原有版本不被覆盖或删除。"**

核心原则：**Restore = Create New Draft** — 永远不覆盖、不删除已有版本。

用户能够：
- 选择任意历史版本，基于它创建新草稿
- 新草稿自动成为最新版本（version = max + 1）
- 原有版本保留完整，可追溯
- 恢复前确认，恢复后可见

## 2. Scope

### In Scope
- **createRestoredDraft Repository 方法** — 事务保证的原子操作
- **restoreDraftVersion Server Action** — 后端入口 + 错误映射
- **DraftVersionRestoreButton 组件** — 恢复按钮 + 确认对话框
- **集成到 DraftVersionHistory** — 恢复成功后自动选中新版本
- **所有权验证** — Draft → Topic → Project → User 四级校验
- **版本号递增** — 事务内读取 max version，防止并发冲突

### Out of Scope
- 在线编辑历史版本内容
- 删除历史版本
- 恢复时修改内容（完整复制）
- 版本合并（merge）
- 恢复策略评估/评估数据（仅复制 content/title/outline）
- AI 辅助恢复建议

## 3. Out of Scope (Hard Limits)

- **No overwriting** — 绝不用新内容覆盖旧版本
- **No deletion** — 绝不删除任何历史版本
- **No modification of existing drafts** — 旧版本 immutable
- **No Prisma schema changes** — 不修改数据库模式
- **No Workflow modifications** — Writing/Evaluation/Refine/Humanization/Strategy Approval 不变

## 4. Architecture

```
用户点击「恢复此版本」
       ↓
DraftVersionRestoreButton (client)
       ↓ 显示确认对话框
用户确认
       ↓
restoreDraftVersion(sourceDraftId) [Server Action]
       ↓
topicRepository.createRestoredDraft(sourceDraftId, userId) [Repository]
       ↓
prisma.$transaction(async tx => {
  1. 读取源草稿（含 topic.project）
  2. 所有权校验: draft → topic → project → user
  3. 读取当前 max version
  4. 创建新草稿 (version = max + 1)
})
       ↓
revalidatePath('/projects/(app)') → 页面刷新
       ↓
handleRestoreSuccess(newVersion) → setSelectedVersion + router.refresh()
```

### Transaction Safety

```
┌─────────────────────────────────────────────────────┐
│ prisma.$transaction                                   │
│                                                       │
│ 1. findUnique(sourceDraft)                           │
│ 2. ownership check: project.userId === userId         │
│ 3. findFirst(orderBy version desc) → maxVersion       │
│ 4. create(newDraft, version = maxVersion + 1)         │
│                                                       │
│ All-or-nothing: 任一步失败 → 全部回滚                   │
│ 并发安全: maxVersion 在事务内重新读取，不会重复          │
└─────────────────────────────────────────────────────┘
```

### Error Propagation

```
Repository throws          Server Action maps          User sees
─────────────────────────────────────────────────────────────
SOURCE_DRAFT_NOT_FOUND  →  "该版本不存在或已不可用"    → toast.error
TOPIC_NOT_FOUND         →  "项目上下文不存在"          → toast.error
OWNERSHIP_DENIED        →  "无权操作此版本"            → toast.error
other Error             →  "恢复失败，请稍后重试"      → toast.error
```

## 8. Design Decisions

### 1. Restore = Create New (Not Overwrite)
恢复操作的本质是基于历史内容创建新草稿，而非回滚。这保留了完整的历史轨迹，用户可以随时回溯到任何版本。

### 2. Transaction Wraps All Reads + Write
`findUnique` + `findFirst(maxVersion)` + `create` 全部在事务内执行。并发恢复时，事务隔离保证不会产生重复版本号。

### 3. Ownership Chain Validation
四级校验路径：Draft → Topic → Project → User。确保用户只能恢复自己项目下的草稿。

### 4. Only Content Fields Copied
新草稿仅复制 `title`、`content`、`outline`。评估、策略评估、真人化分析数据不复制（这些是历史分析结果，不适用于新草稿）。

### 5. Status Reset to DRAFT
新草稿状态为 `DRAFT`，不继承源草稿的 `FINAL`/`HUMANIZED` 等状态（新草稿尚未走完流程）。

### 6. Client-Driven Auto-Select
恢复成功后，Server Action 返回新草稿的 version，客户端立即 `setSelectedVersion(newVersion)` + `router.refresh()`。用户在新旧版本间无缝切换。

## 9. Limitations

1. **不复制分析数据** — Evaluation/StrategyEvaluation/Humanization 不随恢复复制
2. **不支持部分恢复** — 只能完整复制 title/content/outline，不能选择性恢复字段
3. **无恢复预览** — 恢复前只能查看源版本内容，无法预览恢复后的新草稿
4. **无批量恢复** — 一次只能恢复一个版本
5. **无恢复历史元数据** — 新草稿不记录"从 vN 恢复"的来源信息
6. **数据库未配置时不可用** — Server Action 提前返回错误
