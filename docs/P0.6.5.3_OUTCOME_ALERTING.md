# P0.6.5.3 — Outcome Alerting

**Status:** COMPLETED
**Date:** 2026-10-02

## 1. Overview

Outcome Alerting is a deterministic alerting system built on top of Outcome Memory.

### Core Principles

- **Outcome = immutable fact** — Outcome is read-only observation record
- **Alert = mutable signal** — Alert is mutable lifecycle state machine
- **Deterministic evaluation** — Pure function, no DB/LLM/network calls
- **Deterministic dedup** — Fingerprint = hash(ruleId:outcomeId), UNIQUE constraint
- **Owner isolation** — Every query includes WHERE ownerId = ?
- **Optimistic concurrency** — version-based updateMany, OCC guarantee

## 2. Architecture

```
OutcomeMemoryService (P0.6.5.2)
    → OutcomeMemory (immutable)
    → OutcomeAlertService.evaluateOutcome()
    → OutcomeAlertEvaluator (pure function, DB-free)
    → OutcomeAlert (mutable signal)
    → OutcomeAlertStore (interface)
    → PrismaOutcomeAlertStore → SQLite
```

## 3. Data Models

### OutcomeAlertRule
- enabled, severity, outcomeType/targetType/targetId filter, metricConditions (AND semantics)

### OutcomeAlert
- Rule + Outcome IDs, severity, status, title, message, matchedConditions, timestamps, version, fingerprint
- Status state machine: open → acknowledged → {resolved|suppressed} (terminal)

### Prisma Schema
- 13 fields including UNIQUE fingerprint, 8 composite indexes
