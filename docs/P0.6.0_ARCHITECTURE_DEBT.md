# 2. P0 级债务 (必须修)

## CTX-001: 知识库静态硬编码

| 属性 | 值 |
|------|-----|
| Area | Knowledge |
| Problem | 24 个知识单元以 JSON 文件硬编码，无法运行时动态添加、修改或删除知识 |
| Evidence | `src/knowledge/knowledge-data.ts` 导入 `VALIDATED_KNOWLEDGE_UNITS.json`，然后 `KNOWLEDGE_UNITS` 作为常量导出。所有检索、索引、嵌入均基于此静态数组 |
| Impact | 知识库规模受限，无法通过用户行为或系统学习动态扩展 |
| Priority | P0 |
| Future Phase | P0.6.2 (知识库 CRUD) |

## CTX-002: 无 Outcome Loop

| 属性 | 值 |
|------|-----|
| Area | Outcome |
| Problem | 系统无法追踪内容发布后的效果数据（互动、转化、反馈），无法形成闭环学习 |
| Evidence | `Topic.status` 有 `PUBLISHED` 状态，但无 OutcomeRecord 模型，无效果追踪 API。Evaluation 仅在生成阶段运行，无 Post-Publication 评估 |
| Impact | 系统无法自我优化，AI 无法从历史表现中学习 |
| Priority | P0 |
| Future Phase | P0.6.5 (Outcome Loop) |

## CTX-003: Decision Memory 缺失

| 属性 | 值 |
|------|-----|
| Area | Memory |
| Problem | 用户决策（角度选择、策略审批、精修接受/拒绝、人工编辑修改）仅存在于操作时刻，未形成持久、可查询、可复用的记忆 |
| Evidence | `ContentStrategy.approvalStatus` 记录审批结果但无上下文。`Draft.changeReason` 仅文本字段。`Humanization.adopted` 仅布尔值。无 Decision 实体模型。无 "为什么做出这个决定" 的结构化记录 |
| Impact | 系统无法学习用户的决策模式，无法在类似场景下提供更好的默认建议 |
| Priority | P0 |
| Future Phase | P0.6.4 (Decision Memory) |

## CTX-004: Prompt 体积增长无管控

| 属性 | 值 |
|------|-----|
| Area | Generation |
| Problem | Writing Prompt 包含 7+ 个上下文模块 (topic/strategy/angle/persona/audience/knowledge/source + expressionPlan)，某些模块阈值截断 (sourceContent 5000字) 但无整体预算控制 |
| Evidence | `skills/writing/prompts.ts:54-160`，WRITING_PROMPT 函数组装的 prompt 调用包含 11 个参数，最终 prompt 估计 8000-15000 tokens |
| Impact | Token 成本不可控，长 prompt 可能挤压 LLM 生成空间、降低输出质量 |
| Priority | P0 |
| Future Phase | P0.6.2 (Context Assembly Engine) |

## CTX-005: 跨 Project 上下文完全隔离

| 属性 | 值 |
|------|-----|
| Area | Context |
| Problem | 不同 Project 之间的 Topic 完全隔离。用户在一个 Project 中的策略选择、风格偏好、成功角度无法自动帮助另一个 Project |
| Evidence | 无跨 Project Context 共享机制。`UserWritingProfile` 是全局唯一的 (userId @unique)，提供了有限的风格记忆，但不包含：决策历史、成功模式、失败教训 |
| Impact | 用户每次新建 Project 都需要"重新教育"系统 |
| Priority | P0 |
| Future Phase | P0.6.3 (Memory Layer) |

# 3. P1 级债务 (应该修)

## CTX-006: 无显式 Intent 模型

| 属性 | 值 |
|------|-----|
| Area | Intent |
| Problem | 用户意图隐式承载于 Topic.goal (文本) 和 Topic.contentType (枚举)，无结构化意图模型 |
| Evidence | `prisma/schema.prisma:72-75` Goal 和 constraints 均为 `String?`，非结构化。无 Intent Entity。Workflow 中无 Intent 演化追踪 |
| Impact | AI 无法精确理解用户"想要什么"，无法做意图驱动的内容优化 |
| Priority | P1 |
| Future Phase | P0.6.1 (Context Object Foundation) |

## CTX-007: Memory 无分层架构

| 属性 | 值 |
|------|-----|
| Area | Memory |
| Problem | 当前 Memory 实现散落各处 (WritingProfile/ActiveDraft/AgentRun/ChangeReview)，无统一 Memory Layer 概念，无 Static/Dynamic/Episodic/Semantic 分层 |
| Evidence | `UserWritingProfile` 在基础设施层，`ActiveDraft` 在工作流层，`AgentReviewStatus` 在 UI 状态层。无统一 Memory 接口或抽象基类 |
| Impact | 难以实现记忆的自动过期、优先级排序、跨类型关联 |
| Priority | P1 |
| Future Phase | P0.6.3 (Memory Layer) |

## CTX-008: 知识库规模限制 (24 KU)

| 属性 | 值 |
|------|-----|
| Area | Knowledge |
| Problem | 生产级知识库通常需要 100-1000+ 知识单元，当前 24 KU 远不足以覆盖内容创作的知识需求 |
| Evidence | `docs/p0.2.2.1/VALIDATED_KNOWLEDGE_UNITS.json` — 24 units，8 categories。语义检索的 TopK=5 已经能覆盖超过 20% 的知识库 |
| Impact | 知识注入的信息密度低，AI 经常"无知识可注入" |
| Priority | P1 |
| Future Phase | P0.6.2 |

## CTX-009: AgentRun 记录不完整

| 属性 | 值 |
|------|-----|
| Area | Observability |
| Problem | AgentRun 模型已定义但仅在部分 Skill 被记录，且缺少 prompt 内容、完整上下文快照、用户反馈关联 |
| Evidence | `agent-run-repository.ts` 仅提供 `create` 方法，但 `content-service.ts` 外的 Skill 调用很少记录 AgentRun。无 prompt 字段 |
| Impact | 难以做全链路追踪和成本归因分析 |
| Priority | P1 |
| Future Phase | P0.6.2 或 P0.7 |

## CTX-010: WorkflowState 单体过大

| 属性 | 值 |
|------|-----|
| Area | Frontend Architecture |
| Problem | `use-workflow.ts` 686 行，包含 40+ actions，管理整个创作流程的所有状态。违反单一职责原则 |
| Evidence | `src/hooks/use-workflow.ts:1-686`，包含 TopicProfile/SearchedContent/ViralResult/AudienceInsight/Angle/Strategy/Draft/Evaluation/Humanization 所有类型定义和状态 |
| Impact | 难以测试、难以复用、难以维护 |
| Priority | P1 |
| Future Phase | 可在 P0.6.x 后期拆分，但非紧迫 |

## CTX-011: Topic Status 无历史记录

| 属性 | 值 |
|------|-----|
| Area | Context |
| Problem | Topic.status 仅保存当前状态。无法回看项目经历了哪些阶段、每个阶段停留了多久、是否有回退 |
| Evidence | `prisma/schema.prisma:76` — `status String @default("DRAFT")`。更新时直接覆盖，无历史表 |
| Impact | 失去 Episodic Memory 的一部分，无法做项目复盘 |
| Priority | P1 |
| Future Phase | P0.6.4 或 P0.6.6 |

## CTX-012: 无 Context Assembly 标准层

| 属性 | 值 |
|------|-----|
| Area | Context |
| Problem | 每个 Prompt 构造函数独立组装上下文，无统一的 Context Assembly 层。同一个 Context 维度（如 Persona）在不同 Skill 中的注入方式可能不一致 |
| Evidence | `WRITING_PROMPT()` vs `CONTENT_STRATEGY_PROMPT()` vs `EVALUATION_PROMPT()` — 各自独立组装，persona 在某些 prompt 中出现/不出现 |
| Impact | 上下文注入的不一致性，难以确保所有 AI 调用组合都收到必要的上下文 |
| Priority | P1 |
| Future Phase | P0.6.2 (Context Assembly Engine) |

# 4. P2 级债务 (可以等)

## CTX-013: 无多用户支持

| 属性 | 值 |
|------|-----|
| Area | Identity |
| Problem | 系统硬编码 Single-User 模式 (`getDefaultUserId()`)，无法支持多用户场景 |
| Evidence | `src/lib/utils/default-user.ts` — 返回固定 userId。所有 Repository 查询均基于此 |
| Impact | 无法部署为多用户 SaaS |
| Priority | P2 |
| Future Phase | P1.x (产品化) |

## CTX-014: Persona 无版本管理

| 属性 | 值 |
|------|-----|
| Area | Identity |
| Problem | Persona 修改后立即生效，无版本历史。无法知道某个 Topic 使用的是哪版 Persona |
| Evidence | `prisma/schema.prisma:47-61` Persona Model 无 version 字段。Topic→Persona 关联为 SetNull |
| Impact | Persona 变更导致历史策略/内容分析困难 |
| Priority | P2 |
| Future Phase | P0.6.x 后期 |

## CTX-015: JSON 字段无运行时校验

| 属性 | 值 |
|------|-----|
| Area | Data Integrity |
| Problem | 大量 Prisma `Json?` 字段 (20+ 处) 仅有 TypeScript 类型约束，无运行时 Schema 校验 |
| Evidence | `Draft.outline`, `Content.keywords`, `Content.emotions`, `Evaluation.suggestions` 等均为 Json? |
| Impact | 数据一致性依赖 Skill 层的 Zod 校验，存在数据腐化风险 |
| Priority | P2 |
| Future Phase | 可在 Model 层逐渐增加校验，非紧迫 |

## CTX-016: 缺少 Knowledge Graph

| 属性 | 值 |
|------|-----|
| Area | Knowledge |
| Problem | 知识单元之间无显式关系（语义相关性由 embedding 隐式表达），无概念网络/知识图谱 |
| Evidence | `knowledge-context-types.ts`、`types.ts` 中均无关系模型。`CanonicalKnowledgeUnit` 无 related_knowledge 字段 |
| Impact | 无法做推理链、概念路径、知识传播等高级能力 |
| Priority | P2 |
| Future Phase | P0.6.6 或 P0.7 |

# 5. P3 级债务 (将来再说)

## CTX-017: 无 Context Pollution 检测

| 属性 | 值 |
|------|-----|
| Area | Context Quality |
| Problem | 当前无机制检测 prompt 中的冲突、重复、过期上下文。全部依赖 Prompt 作者的直觉 |
| Evidence | 无相关代码 |
| Impact | 难以量化 Context 质量 |
| Priority | P3 |
| Future Phase | P0.7+ |

## CTX-018: 无 Workflow 可视化

| 属性 | 值 |
|------|-----|
| Area | Observability |
| Problem | ARCHITECTURE.md 规划了 React Flow 做 Workflow 可视化，但未实现 |
| Evidence | 旧 ROADMAP 中 Phase 3 提及 "Workflow Visualization + React Flow"，但当前无相关代码 |
| Impact | 用户无法直观看到自己在创作流程中的位置和决策路径 |
| Priority | P3 |
| Future Phase | P1.x+ |

## CTX-019: 无 LiteLLM / Model Gateway

| 属性 | 值 |
|------|-----|
| Area | AI Infrastructure |
| Problem | 直接依赖环境变量选择 Provider，无中间 Gateway 层，无自动 failover |
| Evidence | `src/lib/ai/models.ts` — 通过 env 变量硬编码选择 Provider。无 failover 逻辑 |
| Impact | Provider 服务中断时系统完全不可用 |
| Priority | P3 |
| Future Phase | P1.x+ |
