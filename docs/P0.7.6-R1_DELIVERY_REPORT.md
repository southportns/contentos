function generateRunId(request: ContextOSRuntimeRequest, timestamp: string): string {

## 二、Run ID 冲突解决方案与幂等语义

### 2.1 ID 格式

```
run_{ownerId}_{taskId?}_{contentHash}_{timestamp}
```

示例：
```
run_alice_   a1b2c3d4_1760176000000          (无 taskId)
run_alice_taskX_a1b2c3d4_1760176000000      (有 taskId)
```

### 2.2 字段契约

| 字段 | 角色 | 性质 |
|------|------|------|
| `ownerId` | 隔离 | 安全边界，不影响冲突 |
| `taskId` | **追踪标识** | 当时代进 ID，不同任务即使其他字段相同也不会合并 |
| `contentHash` | **去重哈希** | `{purpose, input}` 的 djb2 摘要（8 字符 base-36） |
| `timestamp` | 时间戳 | 隔离毫秒级重复 |

### 2.3 幂等键定义

合法的"相同 Run"重试必须 5 个字段完全一致：
`(ownerId, taskId, purpose, input, timestamp)`

**taskId 不是幂等键**。不同请求使用相同的 taskId 会产生不同 Run（因为 purpose/input 不同 → contentHash 不同）。

**contentHash 保障了即使 timestamp 相同也不会冲突**。两个完全不同的请求不会静默合并。

### 2.4 哈希冲突概率

- djb2 输出 8 字符 base-36 ≈ 2^42 空间
- 千级请求量时碰撞概率 < 10^-9
- 碰撞时 `runStore.create()` 抛 `ContextOSRuntimeError` 明确报错（不会静默覆盖）

## 三、Learning 状态定义（4 态明确区分）

| 状态 | 含义 | diagnostics | 触发条件 |
|------|------|-------------|---------|
| `completed` | 候选处理完成，无持久化失败 | `completed` 或 `skipped` | `counts.failed === 0` |
| `no_evidence` | Resolver 成功返回空数组（无可用证据） | `skipped` | `learningSources.length === 0` |
| `skipped` | 学习管线未执行（memoryStore 未配置） | `skipped` | `!dependencies.memoryStore` |
| `failed` | 存在失败项或解析异常 | `failed` | resolver 接入异常 或 `counts.failed > 0` |

**关键不变量：**

- Agent 成功 ≠ Learning 成功（Run 可以 `completed` 同时 learning `failed`）
- 没有证据 ≠ 证据解析没有出错（resolver 异常 → `failed`，`[]` → `no_evidence`）
- Owner 不匹配 → fail-closed（任何 MemoryStore 写入前拒绝）
