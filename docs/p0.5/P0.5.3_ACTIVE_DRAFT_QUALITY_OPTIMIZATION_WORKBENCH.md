# P0.5.3 — Active Draft Quality & Optimization Workbench

## Status: COMPLETED

## Overview

P0.5.3 implements the Quality & Optimization Workbench for the active draft,
enabling content evaluation, issue-driven refinement, and AI-style humanization
— all persisted as new draft versions (never overwriting existing drafts).

## Architecture

### Component Hierarchy
```
ProjectDetailPage
  └── ProjectDetailQualityWorkbench
        ├── DraftQualityPanel (evaluation display + issue selection)
        ├── DraftHumanizationPanel (preview + adopt/dismiss)
        └── Server Actions (evaluate, refine, previewHumanize, adoptHumanize)
```

### Data Flow
```
Active Draft → Evaluate → Evaluation persisted against draft
             → Refine (issue_fix mode) → New Draft v(N+1) created
             → Preview Humanization → In-memory result (no DB write)
             → Adopt Humanization → New Draft v(N+1) created + Humanization record
```

## Deliverables

### New Repository Methods (`src/lib/repositories/topic-repository.ts`)
1. **`upsertDraftEvaluation`** — Upserts evaluation+dimension scores against a draft
2. **`createRefinedDraft`** — Creates new draft version from refine output (issue_fix mode)
3. **`createHumanizedDraft`** — Creates new draft version from humanization output + binds Humanization record

### New Server Actions (`src/lib/services/server-actions.ts`)
1. **`evaluateActiveDraft`** — Calls evaluation API, persists result via upsertDraftEvaluation
2. **`refineActiveDraft`** — Calls refine API with selected issues, creates new draft version
3. **`previewHumanization`** — Calls humanization API, returns result without persistence
4. **`adoptHumanizedDraft`** — Preview + createHumanizedDraft in single flow

### New UI Components
1. **`draft-quality-panel.tsx`** — Evaluation results display, score grid, issue selection for refine
2. **`draft-humanization-panel.tsx`** — Humanization preview, adopt/dismiss, detection list
3. **`project-detail-quality-workbench.tsx`** — Orchestrator connecting panels + server actions

## Design Decisions

1. **New Draft on Refine/Humanization** — Never overwrites existing draft; each creates a new version
2. **Preview-first Humanization** — Preview is in-memory only; explicit adopt creates draft
3. **Evaluation Bound to Draft** — Persisted against source draft via upsert
4. **"当前" Badge Support** — UI indicates when highest-version draft is not the active draft
5. **Cross-tab Sync** — New drafts broadcast via existing useActiveDraftSync hook
