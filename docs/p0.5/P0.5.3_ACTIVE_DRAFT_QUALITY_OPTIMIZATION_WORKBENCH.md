# P0.5.3 — Active Draft Quality & Optimization Workbench

## Status: COMPLETED (with Final Hardening)

## Overview

P0.5.3 implements the Quality & Optimization Workbench for the active draft,
enabling content evaluation, issue-driven refinement, and AI-style humanization
— all persisted as new draft versions (never overwriting existing drafts).

A subsequent **Final Hardening** phase addressed 4 critical gaps found during
integration testing: missing evaluation context, persisted evaluation hydration,
OCC race conditions, and cross-component dirty state synchronization.

## Architecture

### Component Hierarchy
```
ProjectDetailPage [Server Component]
  └── DraftEditor ─── DirtyStateStore (shared)
  └── ProjectDetailQualityWorkbench ─── isEditorDirty from store
        ├── DraftQualityPanel (evaluation display + issue selection)
        ├── DraftHumanizationPanel (preview + adopt/dismiss)
        └── Server Actions (evaluate, refine, previewHumanize, adoptHumanize)
```

### Data Flow
```
Active Draft → Evaluate → Evaluation persisted against draft
             → Refine (issue_fix mode) → New Draft v(N+1) created (OCC-checked inside tx)
             → Preview Humanization → In-memory result (no DB write)
             → Adopt Humanization → New Draft v(N+1) created (OCC-checked inside tx)
```

### Dirty State Store (`dirty-state-store.ts`)
A lightweight pub/sub store using React `useSyncExternalStore` that allows
`DraftEditor` to signal the `Workbench` that unsaved edits exist, preventing
accidental cross-tab refresh with stale content.

## Final Hardening Fixes

### Fix 1: Evaluation Context Injection
**Problem**: `evaluateActiveDraft` Omitted `strategy` and `selectedAngle` from context.
**Fix**: Server action now passes `strategy.selectedAngle.title` and `strategy.category` as context to evaluation API.

### Fix 2: Persisted Evaluation Hydration
**Problem**: `ProjectDetailQualityWorkbench` Never re-loaded existing evaluation from DB on mount.
**Fix**: Added `key={activeDraft.id}` reset mechanism in page.tsx — when activeDraft changes, the workbench remounts and loads the correct persisted evaluation.

### Fix 3: OCC Race Condition (Refine/Humanize)
**Problem**: OCC check (`activeDraftId === sourceDraftId`) Was outside the DB transaction, creating TOCTOU window.
**Fix**: Moved check inside `$transaction()` — both the read (`findUnique`) and the write happen atomically.

### Fix 4: Cross-Component Dirty State Sync
**Problem**: `Workbench` Had no visibility into `DraftEditor`'s dirty state during cross-tab refresh.
**Fix**: Created `DirtyStateStore` — DraftEditor calls `setEditorDirty(topicId, true)` on changes; Workbench blocks refresh when dirty.

## Design Decisions

1. **New Draft on Refine/Humanization** — Never overwrites existing draft; each creates a new version
2. **Preview-first Humanization** — Preview is in-memory only; explicit adopt creates draft
3. **Evaluation Bound to Draft** — Persisted against source draft via upsert
4. **"当前" Badge Support** — UI indicates when highest-version draft is not the active draft
5. **Cross-tab Sync** — New drafts broadcast via existing useActiveDraftSync hook
6. **Atomic OCC** — All active draft checks now inside `$transaction()` boundaries
7. **Key-based State Reset** — Leverage React's `key` prop instead of useEffect for state reset
8. **Shared Dirty Store** — Lightweight `useSyncExternalStore` pattern for cross-component sync without prop drilling
