# P0.5.1 — Active Draft Editor Integration

## Status: PASS

## Overview

P0.5.1 integrates the "Active Draft" concept (introduced in P0.4) into the content editing workflow. The core principle is:

> **Manual edits create new `MANUAL_EDIT` drafts instead of overwriting old versions.**

This preserves complete editing history while giving users a seamless inline editing experience.

## Goals

1. **Editor binding**: Editor binds to the active draft (not `drafts[0]`)
2. **Version preservation**: Save creates a new draft; old versions untouched
3. **Dirty state protection**: Dirty editor silently blocks cross-tab overwrites
4. **Atomic transactions**: Version creation + activeDraftId update in single transaction
5. **Cross-tab awareness**: Broadcast after save; remote refresh for clean editors
6. **User experience**: Inline title/content editing with visible version context
7. **Stale active draft protection**: Server-side OCC check prevents stale data overwrite

## Architecture

### Component Flow

```
Project/[id]/page.tsx
  ↓
 Reads topic.activeDraft + allDrafts (Typed: Topic & { activeDraft: Draft | null })
  ↓
 <DraftEditor activeDraft={...} allDrafts={...} topicId={...} />
  ↓
 useActiveDraftSync (cross-tab sync)
  ↓ onChange → isDirty=true
  ↓ onSave → saveManualDraftEdit(sourceDraftId, content, title)
  ↓ success → broadcastActiveDraftChange → router.refresh()
  ↓ refresh → handleRefreshFromRemote (full state reset: title, content, refs, isDirty, conflict)
```

### Data Flow

```
User Edit → isDirty=true → Click Save
  ↓
saveManualDraftEdit(sourceDraftId, content, title)
  ↓
[Server Action Error Mapping]
  SOURCE_DRAFT_NOT_FOUND → 源草稿不存在，请刷新页面重试
  TOPIC_NOT_FOUND        → 主题不存在，请刷新页面重试
  OWNERSHIP_DENIED       → 无权操作此草稿
  DRAFT_VERSION_CONFLICT → 版本冲突，请刷新后重试
  ACTIVE_DRAFT_CONFLICT  → 当前版本已在其他标签页更新，请刷新后重试
  (other)                → 保存失败，请稍后重试
  ↓
createManualEditDraft({ sourceDraftId, content, title, userId })
  ↓
prisma.$transaction {
  1. OCC CHECK: sourceDraft.topic.activeDraftId === sourceDraft.id
     (throws 'ACTIVE_DRAFT_CONFLICT' if stale — another tab already superseded this draft)
  2. Re-read max version (inside tx, for freshness)
  3. Create new Draft (version++, parentDraftId=sourceDraft.id)
  4. Update Topic.activeDraftId = newDraft.id
}
  ↓
revalidatePath('/projects/(app)')
broadcastActiveDraftChange(topicId, newDraft.id, sourceId)
router.refresh() → props re-render with new active draft
```

### Refresh Flow (Full State Reset)

When a cross-tab change is detected or user clicks "刷新当前版本":

```
handleRefreshFromRemote():
  1. setTitle(activeDraft.title ?? '')
  2. setContent(activeDraft.content)
  3. initialTitleRef.current = activeDraft.title ?? ''
  4. initialContentRef.current = activeDraft.content
  5. setIsDirty(false)
  6. setErrorMessage(null)
  7. setRemoteConflict({ detected: false, remoteDraftId: '' })
  8. router.refresh()
```

This ensures the editor completely discards any local modifications and resets all dirty/conflict state to match the remote active draft baseline.

## Key Design Decisions

### 1. Manual Edit = New Draft (Not Update)

The existing `Draft` model already tracks `version`, `parentDraftId`, `changeType`, `changeReason`. We use `changeType='MANUAL_EDIT'` to distinguish manual edits from RESTORE, AI_GENERATE, etc.

### 2. Monotonic Versioning with Retry

Concurrent edits could produce duplicate versions. Solution:
- Re-read `max(version)` inside the transaction (not before)
- Retry up to 3 times on unique constraint violation (P2002)
- Fallback error: `DRAFT_VERSION_CONFLICT`

### 3. Dirty State Protection

Prevents cross-tab data loss:
- **Clean editor** (not dirty): remote active draft change → `router.refresh()` silently
- **Dirty editor**: remote change → shows amber conflict warning banner, user must choose to refresh or dismiss

### 4. Stale Active Draft Protection (Server-Side OCC)

**Problem**: If Tab A saves (creating v3, activeDraft→v3) and Tab B still has v2 loaded, Tab B's save would create a new v3 based on stale v2 data, potentially losing v3's content.

**Solution**: In `createManualEditDraft`, before executing the transaction:
```typescript
if (sourceDraft.topic.activeDraftId !== sourceDraft.id) {
  throw new Error('ACTIVE_DRAFT_CONFLICT')
}
```

This ensures only the current active draft can spawn children. If another tab has already updated the active draft, the stale tab's save fails with a clear user message.

### 5. Broadcast After Save

The save flow:
1. Create new draft (server action)
2. Update refs to new baseline (`initialTitleRef`, `initialContentRef`)
3. Set `isDirty=false`
4. `broadcastActiveDraftChange()` — notify other tabs
5. `router.refresh()` — re-render with new active draft

### 6. Error Mapping

Database errors mapped to user-friendly Chinese messages:

| Error Code | Message |
|-----------|---------|
| `SOURCE_DRAFT_NOT_FOUND` | 源草稿不存在，请刷新页面重试 |
| `TOPIC_NOT_FOUND` | 主题不存在，请刷新页面重试 |
| `OWNERSHIP_DENIED` | 无权操作此草稿 |
| `DRAFT_VERSION_CONFLICT` | 版本冲突，请刷新后重试 |
| `ACTIVE_DRAFT_CONFLICT` | 当前版本已在其他标签页更新，请刷新后重试 |
| (other) | 保存失败，请稍后重试 |

### 7. Parent Version Display

The editor shows `来源：vN` when the current active draft has a `parentDraftId`. This is computed via `useMemo` from the `allDrafts` prop.

### 8. TypeScript Type Narrowing

The project page uses an extended Prisma type:
```typescript
const topic = data.topic as Topic & { activeDraft: Draft | null }
```

This ensures TypeScript correctly types `topic.activeDraft` for the editor binding, which the base `Topic` model returns as `Draft | null` via relation.
