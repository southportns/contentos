# P0.6.2 — Context Assembly Engine

## Overview

Context Assembly Engine 是一个受约束、可解释、可追踪的上下文组装引擎，负责将分散的 ContextObject 集合转化为结构化的、可直接注入 Prompt 的文本输出。

**核心问题**：解决了 Context 的筛选、排序、去重、预算控制及序列化问题。

**架构定位**：

```
Context Sources → Retrieval → Selection → Ranking → Deduplication → Budget → Package → Serialization → Prompt
```

## Architecture

### Pipeline Stages

| Stage | Module | Responsibility |
|-------|--------|---------------|
| **Select** | `context-selector.ts` | 基于 Kind 和 Project 边界初步筛选 |
| **Rank** | `context-priority.ts` | 基于多维度加权评分的可解释排序 |
| **Dedup** | `context-dedup.ts` | 基于确定性指纹的去重 |
| **Budget** | `context-budget.ts` | Token 估算与预算截断 |
| **Package** | `context-package.ts` | 按 Kind 分组构建结构化包 |
| **Serialize** | `context-serializer.ts` | 转换为 Prompt 可用的文本 |

### Explainable Ranking

排序基于 5 个维度的加权评分：

| Modifier | Weight | Description |
|----------|--------|-------------|
| Base Priority | 固定 | Kind 的基础优先级（identity > intent > strategy > ...） |
| Purpose | +0.3 | 与当前用途（writing/evaluation/strategy）的相关性 |
| Confidence | +0.2 | ContextObject 的置信度 |
| Relevance | +0.2 | 与当前 Project/Topic 的关联度 |
| Recency | +0.1 | 时间衰减因子 |

每个 `ScoredContext` 包含 `reasons[]` 数组，记录所有对分数有贡献的因子，实现完全可解释。

### Deterministic Deduplication

使用确定性指纹进行去重：

- **Fingerprint**: `kind:type:source` 或 `kind:type:source:id`
- 相同指纹的上下文只保留第一个
- 结果可复现、可测试

### Token Budgeting

基于字符比例的确定性 Token 估算：

- `CHARS_PER_TOKEN = 4`（中英混合场景的经验值）
- 预算分配按排名优先级降序
- `requiredKinds` 机制确保核心上下文在预算紧张时不会被静默删除

### Shadow Integration

Writing Skill 作为首个接入点，采用 **Shadow Integration** 模式：

- Assembly Engine 并行运行，输出通过 `serializeContextPackage()` 序列化
- 序列化文本注入 Writing Prompt 的 `## Context Assembly` 区块
- 无破坏性变更：原有的 `knowledgeContext` 路径保持不变
- 验证完成后可无缝切换为正式集成

## Usage

```typescript
import {
  assembleContexts,
  buildContextPackage,
  serializeContextPackage,
} from '@/context/assembly';

// 1. 组装上下文
const result = assembleContexts({
  contexts: [intentCtx, strategyCtx, knowledgeCtx, identityCtx],
  purpose: 'writing',
  maxTokens: 5000,
  projectId: 'proj_1',
  topicId: 'topic_1',
});

// 2. 构建结构化包
const pkg = buildContextPackage(result);

// 3. 序列化为 Prompt 文本
const serialized = serializeContextPackage(pkg, { includeHeader: true });

// 4. 注入 Prompt
const prompt = `${basePrompt}\n\n## Context Assembly\n${serialized}`;
```

## Design Principles

1. **Constrained** — 明确的边界和限制，不做超出职责的事
2. **Explainable** — 每个决策都有可追溯的原因
3. **Deterministic** — 相同输入始终产生相同输出
4. **Non-breaking** — Shadow Integration 不破坏现有业务
5. **Composable** — 每个阶段独立可测、可替换

## Non-Goals

- 不做 LLM 调用（这是 Skill 层的职责）
- 不做持久化（这是 Repository 层的职责）
- 不做实时缓存（未来优化）
- 不实现所有 Retriever（P0.6.2 仅 Knowledge）
