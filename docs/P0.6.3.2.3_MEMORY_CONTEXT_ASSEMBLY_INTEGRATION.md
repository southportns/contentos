# P0.6.3.2.3 — Memory Retrieval → Context Assembly Integration

**Status**: COMPLETED
**Date**: 2026-09-30
**Version**: 1.0

## Overview

P0.6.3.2.3 integrates persistent Memory Retrieval with the Context Assembly Engine, enabling Memory records from the database to participate in the standard Context Assembly pipeline (Selection → Ranking → Deduplication → Budget → Package → Serialization).

This integration ensures that user memories (writing profiles, content archives, persona preferences, draft context, agent run history) are automatically retrieved, converted to `ContextObject`s, and assembled alongside other context sources — subject to the same scope, budget, ranking, and dedup rules.

## Architecture

```
Persistent Memory (DB)
       ↓
DatabaseMemoryRetriever
       ↓
MemoryRecord[]
       ↓
MemoryContextRetriever          ← NEW (implements ContextRetriever)
       ↓
memoryRecordsToContexts()       ← P0.6.3.1 bridge (reused)
       ↓
ContextObject<MemoryContextPayload>[]
       ↓
merge with existing contexts
       ↓
assembleContexts()              ← EXISTING (unmodified)
       ↓
Selector → Ranker → Deduplicator → Budget → Package
       ↓
ContextAssemblyResult (+ MemoryAssemblyStats)
```

### Key Design Decisions

1. **Single ContextRetriever interface** — `MemoryContextRetriever` implements the same `ContextRetriever` interface as `KnowledgeRetriever`, requiring no changes to the assembly pipeline contracts.

2. **Full pipeline participation** — Memory contexts go through ALL assembly stages (Select → Rank → Dedup → Budget). They never bypass any stage.

3. **Feature-flagged zero-change** — When `MEMORY_CONTEXT_ASSEMBLY_ENABLED` is unset/false, the behavior is 100% identical to standard `assembleContexts()`.

4. **No Memory Layer modification** — The Memory Layer (`MemoryRetriever`, `DatabaseMemoryRetriever`, `MemoryStore`) is NOT modified. Only called.

5. **No Writing Prompt modification** — Existing prompt templates remain unchanged.

6. **Graceful degradation** — Any failure in memory retrieval returns `[]` without breaking the assembly pipeline.

## Feature Flags

### `MEMORY_CONTEXT_ASSEMBLY_ENABLED`

- **Default**: `false` (opt-in)
- **Values**: `'true'` or `'1'` to enable; any other value disables
- **Effect**: When enabled, memory contexts are retrieved and participate in assembly

### `MEMORY_CONTEXT_ASSEMBLY_SHADOW_ENABLED`

- **Default**: `false`
- **Purpose**: Observability mode (shadow stats without changing output)

## API Reference

### `assembleContextsWithMemory(request, memoryOptions?)`

Main entry point for memory-integrated assembly.

```typescript
const { result, memoryStats } = await assembleContextsWithMemory(
  {
    contexts: [ctx1, ctx2],
    purpose: 'writing',
    projectId: 'proj_1',
    topicId: 'topic_1',
    maxTokens: 4000,
  },
  {
    memoryRetriever: new MemoryContextRetriever(new DatabaseMemoryRetriever(store)),
    ownerId: 'user_123',
    scope: 'project',       // optional: explicit scope override
    policy: { minConfidence: 0.7 },  // optional: policy override
    memoryLimit: 10,        // optional: max memory results
  }
);
```

**Returns**: `MemoryAssemblyResult`

```typescript
interface MemoryAssemblyResult {
  result: ContextAssemblyResult;      // Standard result (backward compatible)
  memoryStats: MemoryAssemblyStats;   // Memory-specific stats
}

interface MemoryAssemblyStats {
  retrieved: number;   // Memory records retrieved from DB
  selected: number;    // Passed selection (scope/kind filter)
  deduped: number;     // Removed as duplicates
  included: number;    // In final selection (post-budget)
  enabled: boolean;    // Feature flag state at assembly time
  error?: string;      // Error message if retrieval failed
}
```

### `MemoryContextRetriever`

Implements the `ContextRetriever` interface for memory-backed context retrieval.

```typescript
const retriever = new MemoryContextRetriever(memoryRetriever);
const contexts = await retriever.retrieve(
  { kind: 'memory', projectId: 'p1', topicId: 't1', query: '...' },
  { ownerId: 'user_1', scope: 'project' }
);
```

**Graceful degradation**: Returns `[]` on ANY failure — never throws.

## Scope Mapping

| RetrievalRequest Field | MemoryRetrievalRequest Field | Purpose |
|------------------------|------------------------------|---------|
| `projectId` | `projectId` | Filter boundary |
| `topicId` | `topicId` | Filter boundary |
| `query` | `query` | Passed through (currently unused by DB retriever) |
| `limit` | `policy.maxResults` | Max results limit |
| *(N/A — via MemoryRetrievalParams)* | `ownerId` | **Mandatory security boundary** |

## Security Model

### Owner Isolation
- `ownerId` is **mandatory** for persistent memory retrieval
- Memories are filtered by ownerId at the MemoryRetriever level (DB WHERE clause)
- Cross-user memory leakage is prevented by composite `(id, ownerId)` queries at the DB level

### Scope Boundaries
- **Session scope**: Never enters persistent retrieval — `DatabaseMemoryRetriever.retrieve()` returns `[]` immediately for `scope === 'session'`
- **Empty intersection**: When `effectiveScopes ∩ policy.allowedScopes = []`, returns `[]` (no fallback broadening)

### Graceful Failure
- Memory retrieval failure → `[]` (no contexts lost from other sources)
- Assembly continues normally with non-memory contexts
- Error captured in `memoryStats.error` for observability

## Backward Compatibility

1. **`assembleContexts()` is NOT modified** — existing synchronous assembly works identically
2. **Feature flag OFF** — `assembleContextsWithMemory()` produces identical output to `assembleContexts()`
3. **No new required dependencies** — all existing code paths unaffected
4. **Memory Layer unchanged** — `DatabaseMemoryRetriever`, `MemoryStore`, `PrismaMemoryStore` untouched
5. **Writing prompts unchanged** — no prompt template modifications

## Non-Goals

- NOT modifying `DatabaseMemoryRetriever` logic (scope filtering, owner isolation already handled)
- NOT creating a second Context abstraction (reuses `ContextObject<MemoryContextPayload>`)
- NOT bypassing any assembly stage (full pipeline participation)
- NOT modifying writing prompt templates
- NOT implementing memory write-back from context assembly (read-only integration)
