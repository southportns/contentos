# P0.6.3.3 — Decision Memory Foundation

## 概述

Decision Memory Foundation 实现了一个**结构化的决策记忆系统**，作为 Memory Layer 的专业化实现。它通过 `MemoryRecord<DecisionMemoryPayload>`（`type: 'decision'`）来表达决策数据，无需新建数据库表或独立类型系统，而是完全复用现有的持久化层、检索层和 Context Assembly 集成。

## Architecture

```
┌─────────────────────────────────────────────────────────────────────┐
│                     Decision Memory Architecture                      │
└─────────────────────────────────────────────────────────────────────┘

   DecisionMemory = MemoryRecord<DecisionMemoryPayload>
       │
       ├─── DecisionMemoryFactory → createDecisionMemory()
       │
       ├─── DecisionMemoryService → activateDecision() / supersedeDecision() / reverseDecision()
       │
       ├─── DecisionRetrieval → retrieveDecisionMemories() / getActiveDecisions() / getDecisionHistory()
       │
       └─→ Context Bridge (memory-utils.ts)
              │
              ├─── decisionMemoryToContext() → ContextObject<DecisionContextPayload> (kind='decision')
              └─── tryDecisionMemoryToContext() → DecisionContext | null

   持久化层（完全复用，零修改）：
       MemoryStore → PrismaMemoryStore → SQLite/PostgreSQL
   
   检索层（完全复用，零修改）：
       DatabaseMemoryRetriever → MemoryQueryCriteria { types: ['decision'] }
   
   Context Assembly（完全复用，零修改）：
       MemoryContextRetriever → Context Select → Rank → Dedup → Budget → Package
```

## Core Types

### DecisionStatus

Decision 生命周期状态机：

```
   proposed ──activate──→ active ──supersede──→ superseded
                             │
                             └──reverse──→ reversed
```

| 状态 | 说明 |
|------|------|
| `proposed` | 已记录但尚未生效的决策 |
| `active` | 当前有效的决策 |
| `superseded` | 已被新决策替代 |
| `reversed` | 已被显式撤销 |

### DecisionMemoryPayload

```typescript
interface DecisionMemoryPayload {
  decision: string;              // 决策陈述（必填）
  rationale?: string;            // 决策推理
  alternatives?: DecisionAlternative[];  // 考虑过的替代方案
  evidence?: DecisionEvidence[]; // 支撑证据
  constraints?: string[];        // 约束条件
  assumptions?: string[];        // 假设前提
  expectedOutcome?: string;      // 预期结果
  decisionStatus: DecisionStatus; // 生命周期状态（必填）
  supersedes?: string;           // 所替代的决策 ID
}
```

### DecisionMemory（类型别名）

```typescript
type DecisionMemory = MemoryRecord<DecisionMemoryPayload>;
```

**零新接口**：DecisionMemory 不是独立接口，而是 `MemoryRecord` 的泛型特化。

## 状态映射

Decision Status 与 Memory Status 的 DB 兼容映射：

| DecisionStatus | MemoryStatus | 用途 |
|---|---|---|
| `proposed` | `active` | 在 DB 中视为活跃，支持检索 |
| `active` | `active` | 直接对应 |
| `superseded` | `superseded` | 直接对应 |
| `reversed` | `archived` | 撤销 = 归档 |

映射函数：`decisionStatusToMemoryStatus()` + `memoryStatusesForDecisionStatus()`

## Key Design Decisions

### 1. DecisionMemory IS-A MemoryRecord

不引入平行类型系统。Decision Memory 通过 `MemoryRecord<DecisionMemoryPayload>` 表达，完全复用：
- 持久化（PrismaMemoryStore + MemoryRecordRow）
- 检索（DatabaseMemoryRetriever + MemoryQueryCriteria）
- Context Assembly MemoryContextRetriever（kind='memory'）
- OCC 并发控制（version-based updateMany）
- Owner 隔离（WHERE ownerId = ?）

### 2. Factory 唯一入口

`createDecisionMemory()` 是创建 DecisionMemory 的唯一方式。它处理：
- 必填字段校验（decision, ownerId）
- DecisionStatus 合法性校验
- scope 自动推导（explicit → topic → project → global）
- MemoryStatus 映射（DB 兼容）
- ID 生成（`dec_` 前缀 + UUID）

### 3. Service 层状态流转

`DecisionMemoryServiceImpl` 实现三个核心操作：

**activateDecision**（proposed → active）：
- 校验认证用户 ownership（通过 MemoryStore.getById 的 ownerId 参数）
- 验证当前状态为 `proposed`
- 写入新状态并通过 OCC 保存

**supersedeDecision**（active → superseded）：
- 校验被替代决策的所有权
- 验证旧决策的当前状态为 `active`
- 创建新决策（payload.supersedes = oldDecisionId）并持久化
- 持久化成功后更新旧决策为 `superseded`
- 返回持久化后的新 DecisionMemory

**reverseDecision**（active → reversed）：
- 校验所有权
- 验证当前状态为 `active`
- 写入 `reversed` 状态
- DB status 映射为 `archived`

### 4. 检索复用现有基础设施

`retrieveDecisionMemories()` / `getActiveDecisions()` / `getDecisionHistory()` 三个函数包裹现有的 `MemoryRetriever.retrieve()`，添加 Decision 特有过滤逻辑：

- **类型过滤**：仅返回 `type === 'decision'` 的记录
- **状态过滤**：基于 decisionStatus（不是 DB status）做后过滤
- **默认行为**：仅返回 `active` + `proposed`（排除 superseded/reversed）
- **历史模式**：`getDecisionHistory()` 返回全状态 + 按 createdAt 降序
- **includeReversed 参数**：可选，true 时包含 reversed 决策

### 5. Context Bridge

`decisionMemoryToContext()` 将 DecisionMemory 包装为 `ContextObject<DecisionContextPayload>`（kind='decision'），使决策上下文可被 Context Assembly 消费：

| DecisionMemory | DecisionContext |
|---|---|
| `payload.decision` | `decisionType` + `selected` |
| `payload.rationale` | `reason` |
| `payload.alternatives` | `alternatives` + `rejected` |
| `ownerId` | `actor` |
| `projectId` / `topicId` | provenance 传递 |

## Design Principles Summary

1. **零新数据库表**：DecisionMemory 使用已有的 MemoryRecord 表
2. **零平行类型系统**：DecisionMemory IS-A MemoryRecord
3. **Factory 唯一入口**：所有创建经过 createDecisionMemory() 校验
4. **Service 状态流转**：Service 层掌控状态机 + 并发 + 权限
5. **检索全复用**：DatabaseMemoryRetriever 不感知 Decision 类型
6. **Context Bridge**：decisionMemoryToContext() 桥接 Decision → DecisionContext
7. **不可删除哲学**：supersede/reverse 只改状态，不删除记录
8. **完全向后兼容**：零修改现有 Assembly/Pipeline/Ranking 逻辑

## P0.6.3.3-R1 — Decision Memory Closure Fix (2026-10-01)

### 修复的三个闭环问题

#### R1-01: supersedeDecision 持久化缺失

**问题**：`supersedeDecision()` 原实现只更新旧决策为 `superseded`，但未将新决策持久化到数据库。导致 supersede 后新决策丢失。

**修复**：重写 `supersedeDecision()` 确保：
1. Step 3：新决策在 `payload.supersedes = oldDecisionId` 后通过 `store.create()` 持久化
2. Step 4：新决策持久化成功后，旧决策才更新为 `superseded`
3. 返回持久化后的新 DecisionMemory

**代码位置**：`src/memory/decision-memory-service.ts`（第 148-243 行）

#### R1-02: 已反转决策无法检索

**问题**：`reversed` 决策在持久化层映射为 `archived` 状态，但默认检索不包含 `archived` 记录，导致用户无法查看已反转的决策。

**修复**：
1. `MemoryPolicy` 新增可选字段 `includeReversed?: boolean`
2. `retrieveDecisionMemories()` 和 `getDecisionHistory()` 接受 `includeReversed` 参数
3. 默认 `false`（隐藏 reversed），`true` 时包含 reversed 决策

**代码位置**：`src/memory/memory-policy.ts`、`src/memory/decision-memory-retrieval.ts`

#### R1-03: 数据库集成测试静默跳过

**问题**：原集成测试在 Prisma 初始化失败时使用 `if (!dbAvailable) return` 静默跳过，无法发现数据库不可用。

**修复**：移除条件判断，让 `execSync('npx prisma db push ...')` 失败时直接抛出异常导致测试失败。

**代码位置**：`src/memory/__tests__/decision-memory-persistence.test.ts`（第 39-50 行）
