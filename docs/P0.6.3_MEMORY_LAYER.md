## Memory Kind Classification

| Kind     | Description                        | Example                                    |
|----------|------------------------------------|--------------------------------------------|
| static   | Long-term stable, rarely changes   | UserWritingProfile, Persona, brand rules   |
| dynamic  | Recent, mutable working state      | Active Draft, current Topic status         |
| episodic | "What happened" event memory       | Draft edits, Topic state changes, AgentRun |
| semantic | Abstracted reusable facts          | "User prefers short sentences"              |

## Memory Scope Classification

| Scope   | Boundary              | Usage                                  |
|---------|-----------------------|----------------------------------------|
| global  | Cross-project         | User-level preferences                 |
| project | Within a project      | Project-specific context               |
| topic   | Within a topic        | Topic-specific working memory          |
| session | Current session only  | Ephemeral state                        |

### Scope Resolution

```
explicit scope -> topicId -> projectId -> global
```

## Memory Layer vs Knowledge Layer vs Context Layer

Knowledge = "What the world is"
  - "Short video openings affect completion rates"

Memory = "What happened to this user/project, and what the system remembers"
  - "User selected conflict openings 8 times in a row"

Context = "What the current task needs to know"
  - "For this writing, consider user's preferred conflict openings"

## Confidence vs Importance

**Confidence** (0.0 - 1.0): How reliable/trustworthy is this memory?
**Importance** (0.0 - 1.0): How important is this memory for future Context Assembly?

These are SEPARATE dimensions:
- Important but uncertain: confidence = 0.4, importance = 0.9 (VALID)
- Confident but unimportant: confidence = 0.9, importance = 0.1 (VALID)

## Scope vs Confidence/Importance

- Scope answers: "CAN it be used?" (boundary)
- Confidence/Importance answer: "SHOULD it be used?" (quality)

These dimensions MUST NOT be conflated.

## Cross-Project Memory Principle

- **global memory**: Can enter multiple Projects
- **project memory**: Only enters its own Project
- **topic memory**: Only enters its own Topic
- **session memory**: Only exists in current Session

And remember: global != automatically trusted. Scope controls access, Confidence/Importance controls quality.

## Bridge: Memory -> Context

The `memoryRecordToContext()` function in `memory-utils.ts` converts a MemoryRecord to a ContextObject<MemoryContextPayload>:

| MemoryRecord Field     | ContextObject Target               |
------------------------|-------------------------------------|
| id                     | id (prefixed `ctx_mem_`)           |
| kind                   | payload.memoryKind                  |
| type                   | type + payload.memoryType           |
| payload                | payload.value                       |
| source                 | provenance.source                   |
| sourceType             | provenance.sourceType               |
| ownerId                | provenance.ownerId                  |
| projectId              | provenance.projectId                |
| topicId                | provenance.topicId                  |
| derivedFrom            | provenance.derivedFrom              |
| confidence             | confidence + payload.confidence     |
| importance             | payload.importance                  |
| createdAt              | createdAt                           |
| updatedAt              | updatedAt                           |
| lastAccessedAt         | payload.lastAccessedAt              |
| accessCount            | payload.accessCount                 |
| expiresAt              | payload.expiresAt                   |
| status                 | payload.status                      |

## Design Constraints Followed

- [x] Memory Layer does NOT depend on Writing Skill
- [x] Memory Layer does NOT depend on specific UI
- [x] Memory Layer does NOT construct prompts
- [x] Memory Layer does NOT call LLM
- [x] Memory Layer does NOT write to database
- [x] Memory Layer does NOT duplicate Knowledge Layer
- [x] Memory Layer does NOT modify P0.5
- [x] Memory Layer does NOT modify Context Assembly algorithm
- [x] Memory Layer is deterministic
- [x] Memory -> Context is explicit one-way bridge

## Boundary: What This Task Does NOT Include

- [ ] Decision Memory
- [ ] Outcome Loop
- [ ] Context Graph
- [ ] LLM automatic memory extraction
- [ ] Memory Embedding
- [ ] Memory automatic learning
- [ ] Database migration (Prisma schema unchanged)
- [ ] Integration with Context Assembly Engine
