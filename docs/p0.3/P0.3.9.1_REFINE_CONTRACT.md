## 1. What Changed

P0.3.9.1 extends the Refine module's data contract layer to accept structured
context from Evaluation, Risk Analysis, and Approved Strategy — enabling future
phases (P0.3.9.2 Evaluation → Refine feedback loop, P0.3.9.3 Humanization) to
build on a stable data foundation.

**Key principle:** This phase is a **Contract Extension**, not a Workflow Integration.
All changes preserve 100% backward compatibility.

## 3. Evaluation Context

Distilled from the full Evaluation output. Only carries what Refine needs:

```typescript
interface RefineEvaluationContext {
  suggestions: Array<{
    id?: string
    section: string
    issue: string
    suggestion: string
    priority: 'high' | 'medium' | 'low'
  }>
  weaknesses: string[]
  scores?: {
    emotionalImpact?: number
    logicalClarity?: number
    novelty?: number
    readability?: number
    utility?: number
    platformFit?: number
  }
}
```

**Design principles:**
- Small surface area — not a 1:1 copy of Evaluation DB model
- No dependency on Prisma Model
- Core information preserved: Issue, Suggestion, Priority, Weaknesses, Scores

---

## 4. Risk Context

Distilled from Risk Analysis output:

```typescript
interface RefineRiskContext {
  overallRiskLevel?: 'safe' | 'low' | 'medium' | 'high'
  risks: Array<{
    id?: string
    category: string
    description?: string
    suggestion?: string
    severity?: 'high' | 'medium' | 'low'
  }>
}
```

**Design principles:**
- Does NOT expose the raw RiskAnalysis DB model
- Only retains what Refine needs for constraint awareness
- `overallRiskLevel: 'safe'` extends the original enum (which was `'low'|'medium'|'high'`) to support a clean bill of health

---

## 5. Approved Strategy Context

Represents the constraint that Refine must NOT destroy:

```typescript
interface RefineApprovedStrategyContext {
  title?: string
  keyArguments?: string[]
  emotionalArc?: {
    start?: string
    middle?: string
    end?: string
  }
  callToAction?: string
  tone?: string
  selectedAngleTitle?: string
}
```

**Principle:** Approved Strategy = constraint, NOT rewrite target.
Refine may optimise expression but must preserve approved strategic elements.

## 7. New Modes

### `issue_fix`

- Purpose: Structured problem resolution using Evaluation suggestions
- Input: `evaluationContext` (preferred), `riskContext` (optional), `approvedStrategy` (optional)
- Behavior: LLM receives original content + specific issues + suggestions + constraints
- Output: `resolvedIssues` / `unresolvedIssues` tracking

### `humanize`

- Purpose: Remove AI-style phrasing, make content sound more human
- Input: `persona` (optional), `platform` (optional)
- Behavior: LLM rewrites to eliminate template patterns, AI vocabulary, empty parallelism
- Output: Each humanization edit tracked in `changes` with type `'humanization'`

## 12. Known Limitations

1. **P0.3.9.2 Evaluation → Refine integration is NOT implemented yet.**
   The contract exists, but the UI does not auto-route evaluation results into refine.
   That wiring happens in P0.3.9.2.

2. **P0.3.9.3 Humanization workflow integration is NOT implemented yet.**
   `humanize` mode exists in schema/prompts/API, but it's not part of the main workflow
   and has no dedicated UI. Full integration comes in P0.3.9.3.

3. **P0.3.9.5 Persistence/versioning is NOT implemented yet.**
   The `RefineOutput` fields exist but are not separately persisted to DB. The `version`
   field in Prisma schema is still not incremented.

4. **issue_fix LLM execution** uses the standard `generateText` path. Fine-tuned
   prompt engineering and structured output validation will improve in P0.3.9.2.
