## 7. Current Refine → Evaluation Feedback Loop

### 7.1 Verdict: **DOES NOT EXIST**

The Evaluation → Refine feedback loop is **completely missing**:

```
Current:
  Evaluation ── produces──→ suggestions[] (with section/issue/priority)
       ↓
  User reads suggestions in Step 4
       ↓
  User navigates to Step 5 (Refine)
       ↓
  Refine has **NO access to evaluation data**
       ↓
  User must MANUALLY translate evaluation suggestions into refine prompts
       ↓
  OR user ignores feedback and uses generic prompts

Desired:
  Evaluation ──→ suggestions[] ──→ Feed into Refine context
       ↓
  Refine receives: [{section, issue, suggestion, priority}]
       ↓
  Refine performs TARGETED modifications per issue
       ↓
  Changes linked to specific evaluation issues
```

### 7.2 What Could Be Done

The Evaluation output already contains exactly what Refine needs:

```typescript
// Already produced by Evaluation:
suggestions: Array<{
  section: string      // Identifies location
  issue: string        // Identifies problem
  suggestion: string   // Identifies desired change
  priority: 'high' | 'medium' | 'low'  // Prioritization
}>
```

**This data structure is perfectly suited to drive targeted Refine operations.**

## 8. Architecture Gaps (Top 5)

### Gap 1: Evaluation → Refine Feedback Loop Missing ⭐ CRITICAL

**Problem**: Evaluation produces actionable suggestions but Refine is blind to them  
**Impact**: User must manually copy evaluation feedback into refine prompts  
**Root Cause**: Refine API and skill don't accept evaluation input  
**Fix Priority**: P0 (highest)

### Gap 2: Humanization Has No UI Integration

**Problem**: Humanization skill exists but has no page or component  
**Impact**: Users cannot access AI-style removal capability  
**Root Cause**: No page at `/create/humanize`, no component, no workflow step  
**Fix Priority**: P1

### Gap 3: Refine is Prompt-Driven, Not Issue-Driven

**Problem**: User must formulate prompts to fix problems LLM already identified  
**Impact**: Inconsistent results, depends on user's prompt engineering skill  
**Root Cause**: No structured input for "fix this specific issue"  
**Fix Priority**: P1

### Gap 4: No Draft Versioning / Diff Tracking

**Problem**: Prisma `Draft.version` field exists but is never incremented  
**Impact**: Cannot compare versions, cannot rollback refine changes  
**Root Cause**: Refine modifies content in-place without creating new versions  
**Priority**: P2

### Gap 5: Humanization Could Be Part of Refine Pipeline

**Problem**: Humanization is a separate standalone with no integration point  
**Impact**: Wasted LLM call potential; double-processing if used separately  
**Root Cause**: Architecture didn't consider Humanization as a Refine mode  
**Priority**: P2

## 9. Recommended P0.3.9 Architecture

### 9.1 Target Pipeline

```
Writing → Approved Strategy (gate: 403 if not approved)
  ↓
Evaluation + StrategyEvaluation + RiskAnalysis (parallel, auto-run)
  ↓
Refine (Step 5) — ISSUE-DRIVEN
  ├── Input: Draft + Evaluation Suggestions + Strategy + Risk
  ├── Modes:
  │   ├── issue_fix (NEW) — target evaluation suggestions
  │   ├── tone_adjust — existing tone_change
  │   ├── hook_optimize — existing hook_select
  │   └── title_optimize — existing title_select
  ├── Humanization: integrated as sub-step
  ├── Output: refined content + changes linked to issues
  ├── User review: accept/reject per change
  └── Versioning: creates Draft v2
    ↓
Final Output (Step 6) — from refined Draft v2
```

### 9.2 Recommended Refine Input Schema

```typescript
// EXTENDED from existing RefineInput
interface RefineInputV2 {
  // === Existing fields (backward compatible) ===
  content: string
  title: string
  hook: string
  wordCount: number
  mode: 'issue_fix' | 'tone_adjust' | 'hook_optimize' | 'title_optimize' | 'full_polish'
  
  // === NEW: Evaluation context ===
  evaluation?: {
    suggestions: Array<{
      section: string
      issue: string
      suggestion: string
      priority: 'high' | 'medium' | 'low'
    }>
    weaknesses: string[]
    scores: {
      emotionalImpact: number
      logicalClarity: number
      readability: number
      platformFit: number
    }
  }
  
  // NEW: Risk context
  riskAnalysis?: {
    overallRiskLevel: 'safe' | 'low' | | 'medium' | 'high'
    risks: Array<{
      category: string
      suggestion: string
    }>
  }
  
  // NEW: Strategy constraints (preserve approved strategy)
  approvedStrategy?: {
    keyArguments: string[]
    emotionalArc: { start: string; middle: string; end: string }
    callToAction: string
    tone: string
  }
  
  // NEW: Platform + Persona
  platform?: string
  persona?: string
}
```

### 9.3 Recommended Refine Output Schema

```typescript
interface RefineOutputV2 {
  content: string
  title: string
  hook: string
  wordCount: number
  
  // Enhanced change tracking
  changes: Array<{
    id: string                    // Unique change ID
    type: 'issue_fix' | 'tone_adjust' | 'hook_replace' | 'title_replace' | 'humanization'
    original: string
    revised: string
    reason: string
    linkedIssue?: string          // ← NEW: which evaluation issue this fixes
    confidence?: number           // ← NEW: how confident the fix is
  }>
  
  // NEW: Issue resolution tracking

}
```

## 15. Key Q&A

### Q1: Does ContextOS already have Refine functionality?

**YES** — A fully functional Refine exists with 4 modes:
- `tone_change`: AI modifies based on user prompt
- `hook_select`: Generate & apply hook candidates
- `title_select`: Generate & apply title candidates
- `hook_and_title_select`: Combined generation (efficient)

It has API, skill, schema, UI, state management, and changelog tracking. The UI supports 3 tabs and direct editing.

### Q2: Does Evaluation feedback actually reach Refine?

**NO** — This is the **critical gap**.

- Evaluation runs in Step 4 (Generate) and produces `suggestions[]` with section/issue/suggestion/priority
- Step 5 (Refine) receives **zero** evaluation data
- User must manually translate evaluation suggestions into natural-language prompts
- This causes: inconsistent fixes, ignored feedback, duplicated effort

### Q3: Do Humanization and Refine have overlapping responsibilities?

**NO** — They are complementary:

- **Refine**: Content polish (structure, hook, title, tone) — "make it better"
- **Humanization**: AI-style removal (8 patterns: template, empty, parallel, etc.) — "make it natural"
- Different input schemas, different prompt strategies, different output schemas
- Both should be part of the same pipeline, in sequence

### Q4: What is the current true source of Final Output?

```
Final Output = refineData (localStorage) || draft (localStorage)
             ↓
   User can edit in Step 6 textarea
             ↓
   StepFinal.handleSaveEdit → onSetFinalOutput → workflowActions.setFinalOutput
             ↓
   SaveProjectButton → /api/projects/save → DB (UserContentArchive)
```

**True source chain**: `Writing → Draft → (optional) Refine → (optional) User Edit → Final → Archive`

**NOT from**: Humanization (not in final pipeline), Evaluation (display only)

### Q5: What is the single core problem P0.3.9 should solve first?

## Evaluation → Refine Feedback Loop

The #1 architecture priority is connecting Evaluation output to Refine input.

**Why**: 
- Evaluation already produces exactly the data Refine needs (section/issue/suggestion/priority)
- Without this connection, all other improvements are superficial
- It's the highest-leverage change with the smallest surface area

**Proposed solution** (2 files modified):
1. Extend `RefineInput` schema to include optional `evaluation` field
2. Modify `runRefine` prompt to incorporate evaluation suggestions when available
3. Update StepRefine UI to display linked issues next to changes
