## 1. Current Retrieval Entry Points

### 1.1 API Layer

**File**: `src/app/api/knowledge/search/route.ts`

- GET endpoint accepting `method=semantic` and `min_similarity` params
- Default method is `'keyword'` (P0.3.6 calibration applies only to explicit semantic calls)

### 1.2 Singleton Instance

- `getSemanticSearchInstance()` — lazy-initialized singleton for API routes
- Wraps `RealSemanticSearch` with `KNOWLEDGE_UNITS` data and `getEmbeddingProvider()`

### 1.3 Production Defaults (P0.3.6 Calibration — 不可修改)

**File**: `src/knowledge/semantic/types.ts`

```ts
DEFAULT_SIMILARITY_THRESHOLD = 0.35  // T=0.35 是负拒绝率跳到 100% 的拐点
DEFAULT_TOP_K = 5                     // 召回与上下文成本的最优平衡
```

### 1.4 Core Retriever

**File**: `src/knowledge/semantic/semantic-retriever.ts`

- `SemanticRetriever.retrieve(query)` — embed query → cosine similarity → threshold filter → topK
- Returns `SemanticRetrievalResponse` with `results: SemanticRetrievalResult[]`
- Each result contains: `knowledge_id`, `similarity`, `knowledge: CanonicalKnowledgeUnit`, `retrieval_method`, `retrieval_reason`

### 1.5 Real Orchestrator

**File**: `src/knowledge/semantic/real-semantic-search.ts`

- `RealSemanticSearch.initialize()` — loads from persistence or syncs from cloud
- `RealSemanticSearch.search(query)` — exactly 1 embed() call per search
- Safety: suspect KUs never returned

## 8. Recommended Integration Point

### 8.1 集成位置：Skills 层

**推荐**: 在 Skills 层注入 Knowledge Context，而非修改 API Route 或前端。

**具体位置**:
1. `skills/content-strategy/index.ts` — 在 `runContentStrategy()` 内注入 Knowledge Context
2. `skills/writing/index.ts` — 在 `runWriting()` 内注入 Knowledge Context

### 8.2 不修改 API Route 的原因

- API Route 负责 HTTP 层逻辑（验证、错误处理、持久化）
- 业务逻辑（检索 + 上下文构建）在 Skills 层更符合架构分层原则
- 避免在 API Route 内新增嵌入调用导致超时风险

### 8.3 不修改前端的原因

- 前端仅负责编排和展示
- Knowledge Retrieval 是后端能力
- 前端修改会增加不必要的复杂度

### 8.4 新文件 vs 修改文件

**推荐方案**: 新增独立模块，通过最小修改接入现有 Skills。

## 12. Risks

### 12.1 高风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 服务器端 embed 调用导致 API 超时 | Generation 请求超时 | 1. 检索失败时降级为纯 LLM（不阻塞）<br>2. 前端添加 loading 提示<br>3. 复用 singleton instance |

### 12.2 中风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Knowledge Context 注入导致 Prompt 超长 | LLM 输出质量下降 | 1. 截断过长的 knowledge text<br>2. 限制 evidence 数量<br>3. 优先 validated KU |
| 检索结果不相关导致内容偏差 | 生成内容被错误引导 | 1. Threshold=0.35 已校准<br>2. 明确标记为 "reference knowledge"<br>3. 空结果时不注入 |

### 12.3 低风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Similarity vs Certainty 语义混淆 | LLM 误把相似度当事实确定性 | 文档明确：similarity ≠ 事实正确率 |
| Candidate KU 被当做 Validated | 降低内容可信度 | 强制标记 status，candidate 警告 |
