## 1. Purpose

KnowledgeContext 是 Semantic Retrieval 与 Generation 之间的**数据契约**。

它解决的核心问题：

```
SemanticRetrievalResponse（检索层输出）
    ↓
KnowledgeContext（标准化数据结构）
    ↓
Skill → Prompt Assembly → LLM
```

**职责边界**：

| 层 | 负责 |
|----|------|
| Retrieval | "找到什么"（query → embed → similarity → topK） |
| KnowledgeContext Builder | "哪些结果应该交给生成"、"如何组织"、"如何保留 Traceability" |
| Skill | "怎么完成这个生成任务" |
| Prompt Assembly | "怎么把任务和上下文交给 LLM" |

---

## 2. Architecture Position

```
HTTP Request
    ↓
API Route（Orchestration）
    ↓
Semantic Retrieval Service（semantic-search-instance.ts）
    ↓
SemanticRetrievalResponse
    ↓
Knowledge Context Builder（P0.3.7.3）
    ↓
KnowledgeContext（本契约 — P0.3.7.2）
    ↓
Knowledge Context Serializer（P0.3.7.4）
    ↓
Skill（content-strategy / writing / ...）
    ↓
Prompt Assembly
    ↓
LLM
```

**关键约束**：

- KnowledgeContext 只携带已有 Knowledge，不产生新知识
- Skills 不自行执行 Retrieval
- Retrieval 层不负责 Prompt 注入

```typescript
  selectedCount: number;

  supportingKnowledge: KnowledgeContextItem[];
  evidence: KnowledgeContextEvidence[];

  metadata: KnowledgeContextMetadata;
```

```typescript
interface KnowledgeContextItem {

  evidenceCount: number;
```


## 5. Traceability

完整的追溯链：

```
Generated Content（生成结果）
    ↓ 引用
KnowledgeContext（上下文）
    ↓ primaryKnowledge[].knowledgeId
Knowledge Unit（知识单元）
    ↓ evidence.items[].evidenceId
Evidence（证据）
    ↓ contentId
Original Content（原始素材）
```

**Traceability 保证**：

1. `KnowledgeContextItem.knowledgeId` → 可追溯到完整 CanonicalKnowledgeUnit
2. `KnowledgeContextEvidence.evidenceId` → 可追溯到 Evidence 记录
3. `KnowledgeContextEvidence.contentId` → 可追溯到原始素材

**不复制完整 Evidence 数据模型** — 通过引用关系实现追溯，避免数据膨胀。

## 6. Empty Context

**Empty KnowledgeContext 是合法状态。**

```typescript
const emptyContext: KnowledgeContext = {
  query: "用户话题",
  retrieval: {
    method: 'semantic',
    threshold: 0.35,
    topK: 5,
    includeCandidates: false,
    retrievedCount: 0,
  },
  selectedCount: 0,
  primaryKnowledge: [],
  supportingKnowledge: [],
  evidence: [],
  constraints: {
    hasCandidates: false,
    maxItems: 5,
    wasTruncated: false,
  },
  metadata: {
    version: '1.0.0',
    createdAt: "2026-09-14T00:00:00Z",
    source: 'p0.3.7',
  },
};
```

**Empty Context 语义**：

- 检索未返回任何结果（无相关知识）
- 或者所有结果被过滤掉
- Generation 应继续正常工作（无知识注入）

**禁止**：

- ❌ 抛异常
- ❌ 随机选择 Knowledge 填充
- ❌ 自动生成事实
- ❌ 强制使用 Knowledge

## 7. Candidate Handling

**当前 P0.3.6 生产配置**：

```
DEFAULT.include_candidates = false
```

即默认检索不主动返回 candidate 状态的 KU。

**Contract 规定**：

1. `status` 字段必须保留原始状态
2. `validated` ≠ `candidate`，不得混淆
3. Candidate 不能通过删除 status 或修改 status 看起来像 validated
4. `KnowledgeContextConstraints.hasCandidates` 明确标记上下文中是否存在 candidate

**如果 include_candidates = false（默认）**：

- `hasCandidates = false`
- 所有 item 的 status = `validated`

**如果 include_candidates = true**：

- `hasCandidates` 取决于实际检索结果
- 部分 item 的 status 可能为 `candidate`
