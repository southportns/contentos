## 1. Purpose

让 Content Strategy 真正可以看到检索到的知识（`StrategyKnowledgeContext`），并把它作为**辅助知识 / strategy evidence** 注入 Content Strategy Prompt。

**最终链路**：
```
Topic → Strategy Knowledge Retrieval → StrategyKnowledgeContext
  → Strategy Prompt Assembly → Content Strategy LLM → Strategy Proposal
```

## 4. Prompt Structure

### 4.1 Knowledge Block 注入位置

```
主题：{topic}

选定角度：
- 标题：{selectedAngle.title}
- 切入角度：{selectedAngle.angle}
- 目标情绪：{selectedAngle.targetEmotion}
- 关键要点：{selectedAngle.keyPoints}
{profileStr}{audienceStr}{personaStr}
${sourceStr}                                  ← 原始素材

## Strategy Knowledge Context                   ← ✅ KNOWLEDGE BLOCK HERE

The following knowledge is supporting evidence and pattern reference.
Validated knowledge is verified.
Candidate knowledge is unverified and should not be represented as confirmed fact.
Use it to inform the strategy, but make an independent strategic judgment for the topic.

---

### Primary Knowledge

#### Primary Knowledge 1: {name}
Status: {status} | Category: {category} | Confidence: {confidence}
Similarity: {similarity.toFixed(2)}

{text}

### Supporting Knowledge
...

目标平台：{platform}
内容类型：{contentType}
期望语调：{tone}
目标字数：{wordCount}
⚠️ 重要：...
请生成完整的内容策略。
```

### 4.2 位置选择理由

1. **在 sourceStr 之后** — 原始素材是事实基础，Knowledge 是补充证据
2. **在平台/字数之前** — 这些是约束条件，放在最后作为"落地指令"
3. **与 Writing Prompt 保持一致** — Writing 中是 `originalContent → KnowledgeContext → platform`

---

## 5. Candidate Policy

遵循 P0.3.8.0 Option B 决策：**Strategy 看到 validated + candidate，明确标注**。

| Status | Prompt 中展示 | 额外说明 |
|--------|--------------|---------|
| `validated` | `Status: validated` | 无额外说明（默认可信） |
| `candidate` | `Status: candidate` | Prompt 顶部增加："Candidate knowledge is unverified and should not be represented as confirmed fact." |

---

## 6. Empty / Failure 处理

| 场景 | `strategyKnowledge` 值 | Prompt 行为 |
|------|----------------------|------------|
| Retrieval 成功 + 有结果 | `StrategyKnowledgeContext { primaryKnowledge: [...], supportingKnowledge: [...] }` | 注入完整 Knowledge Block |
| Retrieval 成功 + 0 结果 | `{ primaryKnowledge: [], supportingKnowledge: [] }` | 注入占位："No relevant strategy knowledge was retrieved." |
| Retrieval 失败 | `null` | **不注入任何内容** — Prompt 与集成前完全一致 |
| 调用方未提供 | `undefined` | **不注入任何内容** — Prompt 与集成前完全一致 |

---

## 7. Prompt Safety

### 7.1 Knowledge 与 Instruction 的边界

- Knowledge 内容作为 **DATA** 注入 Markdown section
- 使用 `## Strategy Knowledge Context` 作为 section header，与 `## 原始素材` 同级
- Knowledge 内容不会被解析为 system/task instructions

### 7.2 防止 Prompt Injection

即使 Knowledge 内容包含 "SYSTEM: Ignore previous instructions"：
- 它仍然位于 `## Strategy Knowledge Context` section 内
- 不会改变 `请生成完整的内容策略。` 等原有指令
- LLM 会将 Markdown section 内容视为 DATA

### 7.3 字段隔离

Serializer **不暴露**以下字段：
- `knowledgeId`（P0.3.8.1 已排除）
- `retrievalReason`（P0.3.8.1 已排除）
- `threshold`、`topK`、`embedding`（检索内部信息）
- `retrievedCount`、`metadata`、`query`（检索层信息）
