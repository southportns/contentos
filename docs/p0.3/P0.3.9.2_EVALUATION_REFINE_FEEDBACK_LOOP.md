# P0.3.9.2 — Evaluation → Refine Feedback Loop

**Status:** COMPLETE
**Date:** 2026-09-17

---

## 1. Problem

Evaluation results (Step 4) were display-only. Users had to:
- Read suggestions manually
- Figure out how to fix them
- Write their own prompt
- Run Refine blindly

**No structured feedback path existed** between Evaluation and Refine.

## 2. Before Architecture

```
Step 4 Generate
  └── Evaluation (display only)
        ├── scores
        ├── suggestions[]
        └── conclusion

Step 5 Refine (evaluation-agnostic)
  └── tone_change / hook_select / title_select
```

**Gap:** Evaluation results never reached Refine. Refine couldn't target specific issues.

## 3. After Architecture

```
Step 4 Generate
  └── Evaluation
        └── suggestions[]
              ↓
    evaluationToRefineIssues()
              ↓
  Workflow State: refineIssues[]
              ↓
Step 5 Refine
  ├── [AI 评价发现的问题]
  │     ☑ 开头吸引力不足    [高]
  │     ☑ 情绪递进较弱      [中]
  │     ☐ CTA 不够明确      [低]
  │
  │     [修复选中问题 (2)]
  │
  └── issue_fix → POST /api/generation/refine
        ↓
  ┌──────────────────────────────┐
  │ Issue Fix Result              │
  │ ✓ 开头吸引力不足              │
  │ ✓ 情绪递进较弱                │
  │ ⚠ CTA 不明确 (未解决)         │
  └──────────────────────────────┘
        ↓
  Changes log with linkedIssueId
```

## 4. Evaluation → Refine Data Flow

```
EvaluationResult (workflow)
      ↓
evaluationToRefineIssues() [adapter]
      ↓
RefineIssue[] (workflow)
      ↓
User selection (toggle)
      ↓
selectedIssues → evaluationContext
                + riskContext (from RiskAnalysisResult)
                + approvedStrategy (from ContentStrategy)
      ↓
POST /api/generation/refine { mode: 'issue_fix', ... }
      ↓
runRefine() → REFINE_ISSUE_FIX_PROMPT()
      ↓
RefineResult {
  resolvedIssues,
  unresolvedIssues,
  preservedElements,
  changes[] { linkedIssueId }
}
      ↓
workflowActions.markRefineIssuesResolved()
      ↓
UI shows ✓ resolved / ⚠ unresolved
```

## 5. RefineIssue Adapter

**File:** `src/lib/workflow/refine-issue-adapter.ts`

### `evaluationToRefineIssues(evaluation)` → `RefineIssue[]`

Converts `EvaluationResult.suggestions[]` into `RefineIssue[]`:
- High-priority = `selected: true` (user must still click fix)
- Medium/Low = `selected: false`
- ID format: `eval-{index}` (fallback, since schema has no explicit suggestion ID)

### `riskAnalysisToRefineRiskContext(riskAnalysis)` → `RefineRiskContext | null`

Converts `RiskAnalysisResult` into the `riskContext` accepted by Refine API. Adds `risk-{index}` IDs.

### Helper Functions
- `toggleIssueSelection(issues, id)` — immutable toggle
- `markIssuesResolved(issues, resolvedIds)` — mark resolved
- `getSelectedIssues(issues)` — filter selected

## 7. issue_fix Execution

When user clicks "修复选中问题":

```
handleFixSelectedIssues()
  ├── Builds evaluationContext from selected issues
  │     ├── suggestions[] { id, section, issue, suggestion, priority }
  │     ├── weaknesses[] (from evaluation)
  │     └── scores (from evaluation)
  ├── Includes riskContext (from workflow.riskAnalysis)
  ├── Includes approvedStrategy (from workflow.strategy)
  └── Calls onRefine({ mode: 'issue_fix', ... })
```

**API Route:** `/api/generation/refine` — already supports P0.3.9.1 contract.

**Skill:** `runRefine()` uses `REFINE_ISSUE_FIX_PROMPT()` for structured issue targeting.

## 8. Resolved / Unresolved Semantics

### Resolved Issue
```typescript
{
  issueId: "eval-0",
  resolution: "重写开场第一句，增加悬念",
  changeId: "chg-001"
}
```

### Unresolved Issue
```typescript
{
  issueId: "eval-2",
  reason: "当前上下文缺少足够的CTA素材",
  suggestion: "用户可补充具体行动号召"
}
```

**Critical safety rule:** If the model cannot fix an issue without fabricating information, it MUST return it as unresolved with an explanatory reason — never hallucinate.

### Preserved Elements
```typescript
{
  element: "核心论点A",
  reason: "Approved Strategy constraint"
}
```

Ensures Refine doesn't destroy approved strategic elements.

## 10. User Manual Override Behavior

**Priority order for content source:**
```
current edited content (manual)
  + applied refineData
    + draft (fallback)
```

Issue Fix always runs against `appliedContent` (manual edits included). The model never overwrites user edits — it only suggests changes on top of the latest content.

## 14. Known limitations

1. **ID Stability:** Issue IDs are `eval-{index}` — stable within a single evaluation session but not across regenerations. If the same issue appears at a different index, it's treated as a new issue.

2. **Single-pass Fix:** All selected issues are sent in one LLM call. If issues conflict (A requires adding content, B requires removing it), the model may produce suboptimal results.

3. **No Incremental Fix:** Each issue_fix run produces a complete revised draft. Re-running fix on already-resolved issues doesn't preserve prior fixes — it re-processes from `appliedContent`.

4. **Weaknesses Merged Level:** `evaluationContext.weaknesses` are sent as a flat list per run, not attached to specific issues. The prompt instructs the model to consider them generally.
