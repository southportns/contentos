## 6. Real DB Test Infrastructure

### 6.1 Approach
Use a separate SQLite test database file (`file:./test.db`) to avoid affecting production `dev.db`. Set `DATABASE_URL` at runtime via environment variable.

### 6.2 Safety Rules
- ✅ Isolated test database (separate file)
- ✅ Test user (`test-user` prefix)
- ✅ Test project (cleanup after test)
- ✅ Automatic cleanup in afterEach/beforeEach
- ❌ NEVER touch production dev.db
- ❌ NEVER modify embeddings storage
- ❌ NEVER modify knowledge units

### 6.3 Implementation Pattern
```typescript
// vitest.config.ts or test setup
process.env.DATABASE_URL = 'file:./test.db';

// In test file
import { prisma } from '@/lib/prisma';
import { execSync } from 'node:child_process';

beforeAll(() => {
  // Push schema to test DB
  execSync('npx prisma db push --skip-generate', { 
    env: { ...process.env, DATABASE_URL: 'file:./test.db' } 
  });
});

afterEach(async () => {
  // Clean up test data
  await prisma.userContentArchive.deleteMany({});
  await prisma.humanization.deleteMany({});
  await prisma.evaluation.deleteMany({});
  await prisma.strategyEvaluation.deleteMany({});
  await prisma.draft.deleteMany({});
  await prisma.contentStrategy.deleteMany({});
  await prisma.angle.deleteMany({});
  await prisma.topic.deleteMany({});
  await prisma.project.deleteMany({});
  await prisma.user.deleteMany({});
});
```
