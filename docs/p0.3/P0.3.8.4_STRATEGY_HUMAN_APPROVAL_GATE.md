## 1. Purpose

在 Strategy 自动注入 Knowledge 辅助生成后，确保人类在 Strategy 进入 Writing 阶段之前有一次显式审查机会。这是 retrieval-augmented generation pipeline 的最后一道人工安全防线。

核心设计原则：
- Knowledge is advisory, not authoritative — 模型可以参考知识，但人类做最终决策
- Approval gate 必须零侵入 — 如果用户跳过/忽略，已有流程保持不变
- State 持久化在 localStorage — 页面刷新后审批状态保留

## 2. State Design

### 2.1 StrategyApprovalState
```typescript
type StrategyApprovalStatus = 'none' | 'pending' | 'approved' | 'rejected'

interface StrategyApprovalState {
  status: StrategyApprovalStatus
  knowledgeAssisted: boolean   // 是否经过 Knowledge 检索
  reviewedAt: number | null    // 最后审批时间戳
  approvedStrategy: ContentStrategy | null
}
```

### 2.2 Actions
| Action | Transition | 说明 |
|--------|-----------|------|
| `setStrategyPending(knowledgeAssisted)` | none → pending | Strategy 生成后调用 |
| `approveStrategy(editedStrategy?)` | pending → approved | 用户通过审批 |
| `rejectStrategy()` | pending → rejected | 用户拒绝 |
| `resetStrategyApproval()` | any → none | 重置所有审批状态 |

---

## 3. Flow

**Before**: [一键生成] → Strategy → Writing → Evaluation → Done

**After**: [生成策略] → Strategy + Pending
                    ↓
            人类审阅 → [通过] → Writing + Evaluation → Done
                    → [重新生成] → Strategy (重新)
