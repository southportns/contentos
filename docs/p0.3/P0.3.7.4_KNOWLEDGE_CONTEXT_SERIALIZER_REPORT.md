# P0.3.7.4 — Knowledge Context Serializer Report

## 1. Status

**COMPLETE**

## 2. Objective

Transform the structured `KnowledgeContext` (produced by P0.3.7.3 Builder) into deterministic, human-readable, low-noise, LLM prompt-ready text for future Generation Prompt injection.

Core function: `serializeKnowledgeContext(context) → string`

## 3. Architecture

```
SemanticRetrievalResponse
        ↓
KnowledgeContextBuilder (P0.3.7.3)
        ↓
KnowledgeContext
        ↓
Knowledge Context Serializer (P0.3.7.4, this module)
        ↓
Prompt-ready Text
        ↓
Future Generation Layer (P0.3.7.5)
```

## 4. Scope

Implemented:

- `serializeKnowledgeContext(context: KnowledgeContext): string` — pure serialization function
- Deterministic output (same input → identical output)
- Explicit `Status: validated` / `Status: candidate` distinction
- `wasTruncated` pass-through from `constraints` (never recomputed)
- Builder ordering preservation (primary group first, then supporting; never re-sorted)
- Empty-context stable placeholder
- Nullish / empty / NaN field guarding (no `undefined` / `null` / `NaN` leakage)
- Input immutability (read-only consumption, zero mutation)
- Export via `src/knowledge/context/index.ts` (single import path)

## 6. Input Contract

Consumes the existing `KnowledgeContext` (P0.3.7.2) **read-only**:

| Field | Used by Serializer |
|-------|--------------------|
| `primaryKnowledge[]` | YES — serialized as `### Primary Knowledge N` |
| `supportingKnowledge[]` | YES — serialized as `### Supporting Knowledge N` |
| `selectedCount` | YES — `Items:` in metadata block |
| `constraints.maxItems` | YES — `Max Items:` |
| `constraints.wasTruncated` | YES — `Was Truncated:` pass-through |
| `query` | NO — retrieval context, not needed by LLM in knowledge block |
| `retrieval.*` (method/threshold/topK/retrievedCount) | NO — retrieval internals (low-noise) |
| `evidence[]` | NO — traceability data, not prompt content |
| `metadata.*` (version/createdAt/source) | NO — contract metadata, not prompt content |

Per-item field policy:

| Item Field | Serialized As |
|------------|---------------|
| `name` | Heading suffix (omitted when empty) |
| `status` | `Status: validated` / `Status: candidate` — never converted |
| `confidence` | `Confidence: high/medium/low` — passthrough, no rescoring |
| `similarity` | `Similarity: 0.91` — `toFixed(2)`, raw 0-1 scale, never percentage |
| `category` | `Category: cognition` etc. |
| `knowledgeLevel` | `Level: strategic_pattern` etc. |
| `evidenceCount` | `Evidence Count: 4` |
| `text` | `Content:` block, verbatim, never truncated/rewritten |
| `knowledgeId` | NOT serialized — internal traceability ID |
| `retrievalReason` | NOT serialized — retrieval debug detail |

## 7. Output Format

```
## Knowledge Context

The following knowledge was retrieved from the validated knowledge base.
Use it as supporting knowledge when relevant.
Do not invent facts that are not present here.

### Primary Knowledge 1: {name}

Status: validated
Confidence: high
Similarity: 0.91
Category: cognition
Level: strategic_pattern
Evidence Count: 4

Content:
{verbatim knowledge text}

### Supporting Knowledge 1: {name}

Status: candidate
...

### Retrieval Metadata

Items: 2
Max Items: 5
Was Truncated: false
```

Empty context output (stable placeholder, no exception):

```
## Knowledge Context

No relevant knowledge was retrieved.
```

## 8. Status Handling

- `validated` and `candidate` are emitted **explicitly and verbatim** as `Status: <value>`
- Candidate is never converted to validated, never visually merged with validated
- `hasCandidates` is implied by per-item `Status:` lines; no separate flag output needed

## 9. Truncation Handling

- `Was Truncated: true|false` is passed through directly from `context.constraints.wasTruncated`
- **Never recomputed** from `items.length`, `retrievedCount`, or any other field (P0.3.7.3.1 semantics preserved)
- When `true`, a stable factual note is appended: `Note: Retrieval results were truncated according to maxItems.`
- No exaggeration ("WARNING: CRITICAL KNOWLEDGE WAS LOST" is deliberately avoided — the Serializer does not know what was truncated)

## 10. Null / Empty Handling

| Input | Behavior |
|-------|----------|
| `items = []` (both groups empty) | Stable placeholder text, no exception |
| `name = ''` | Heading without name suffix |
| `text = ''` | `Content:` section omitted entirely |
| `similarity = NaN` / non-finite | `Similarity:` line omitted |
| `evidenceCount = NaN` / non-finite | `Evidence Count:` line omitted |
| any null/undefined field | Line omitted; `undefined`/`null`/`NaN` never appear in output |

## 11. Determinism

- No `Date.now()`, no `Math.random()`, no random IDs
- `metadata.createdAt` is NOT serialized (timestamp would be noise)
- Iteration order = array order (primary → supporting), no re-sorting
- Number formatting via `toFixed(2)` — locale-independent
- Same input → byte-identical output (verified by TEST 10)

## 12. Ordering & Immutability

- **Ordering**: Builder ranking (status → similarity → confidence → evidence) is fully preserved. Serializer iterates arrays in place without any sort. TEST 11 verifies ascending-similarity input stays ascending.
- **Immutability**: No mutation of `context`, its arrays, or its items. TEST 09 deep-clone comparison verifies `context` is unchanged after serialization.

## 17. Known Limitations

1. **No evidence serialization**: `KnowledgeContextEvidence` is traceability data, intentionally not rendered into prompt text. If a future Generation Prompt needs evidence quotes, that is a P0.3.7.5+ prompt-strategy decision, not a serializer concern.
2. **Fixed text template**: The output template is intentionally hardcoded English structure with verbatim content. Localization / template variants are deferred until a real Generation-layer requirement exists.
