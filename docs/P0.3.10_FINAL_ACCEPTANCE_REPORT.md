## P_RB — Mid-Transaction Rollback

Tests atomicity by creating a SQLite trigger that fires `RAISE(ABORT)` during
`UserContentArchive.create()` — the last write step in the save transaction.
This ensures all prior writes (Project, Topic, Angle, Strategy, Draft, Evaluation,
StrategyEvaluation, Humanization) are properly rolled back.

```
P_RB_1 ✅ Initial save (v1+v2) success
P_RB_2 ✅ Mid-transaction failing save returns error (P2003 Foreign key constraint)
P_RB_3 ✅ No new topic persisted (mid-transaction rollback)
P_RB_4 ✅ No new angle persisted (mid-transaction rollback)
P_RB_5 ✅ No new draft persisted (mid-transaction rollback)
P_RB_6 ✅ No new archive persisted (mid-transaction rollback)
P_RB_7 ✅ Pre-existing strategy approval status preserved after rollback
P_RB_8 ✅ v2 draft content not corrupted by failed save
```

### Trigger mechanism
```sql
CREATE TRIGGER p0310_forced_archive_failure
BEFORE INSERT ON "UserContentArchive"
BEGIN
  SELECT RAISE(ABORT, 'P0.3.10 forced archive failure');
END;
```

Prisma's better-sqlite3 adapter maps `SQLITE_CONSTRAINT_TRIGGER` to `P2003 Foreign key constraint violation`
— confirming the trigger was genuinely invoked and the transaction rolled back at the DB level.
