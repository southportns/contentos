## P_RB Mid-Transaction Rollback — Technical Details

### Mechanism
```
CREATE TRIGGER p0310_forced_archive_failure
BEFORE INSERT ON "UserContentArchive"
BEGIN
  SELECT RAISE(ABORT, 'P0.3.10 forced archive failure');
END;
```

### Transaction Flow Tested
```
Step 1: prisma.user.upsert()         — succeeds
Step 2: prisma.project.update()      — succeeds (existing project)
Step 3: prisma.topic.update()        — succeeds (existing topic)
Step 4: prisma.angle.deleteMany()    — succeeds
        prisma.angle.create()        — succeeds (new angle)
Step 5: prisma.contentStrategy.update() — succeeds (existing strategy)
Step 6: prisma.draft.create()        — succeeds (new drafts)
Step 7: prisma.evaluation.create()   — succeeds
Step 8: prisma.strategyEvaluation.create() — succeeds
Step 9: prisma.project.update(touch) — succeeds
Step 10: prisma.userContentArchive.create()
        ↓ TRIGGER FIRES → RAISE(ABORT)
        ↓ ENTIRE TRANSACTION ROLLS BACK
```

### Verification
- **Before counts === After counts** for ALL 10 entity types
- Pre-existing entities (angle, strategy) preserved intact
- No partial drafts, evaluations, or strategy evaluations from marker transaction
- SQLite trigger dropped immediately after — no side effects on subsequent tests
