# P0.6.5.2 — Outcome Memory Service

## 1. Purpose

Outcome Memory Service provides **lifecycle management** for Outcome Memory records.

While P0.6.5.1 established how to CREATE, STORE, and RETRIEVE Outcome observations, this service governs what happens AFTER creation:

- **Archive**: Move an active outcome to archived state (inactive, excluded from default retrieval)
- **Restore**: Return an archived outcome to active state
- **Batch Import**: Validate and persist multiple outcomes in a single operation

### Architecture Position

```
Outcome Factory (P0.6.5.1)  →  Outcome Memory (immutable snapshot)
         ↓
  OutcomeMemoryService (this)
         ↓
  MemoryStore (interface) → PrismaMemoryStore / MockMemoryStore
         ↓
  Database
```

### What this Service DOES NOT do

This service does NOT:
- Modify Outcome payload — observation data is immutable
- Delete records — only lifecycle transitions
- Connect to Douyin/Xiaohongshu APIs — that's future work
- Implement Alerting/Aggregation/Learning — P0.6.5.3–P0.6.5.5

## 2. State Machine

```
                            active
                              │
                              │ archive
                              ▼
                           archived
                              │
                              │ restore
                              └──────────→ active
```

### Valid Transitions

| From | To | Method | Condition |
|------|----|--------|-----------|
| active | archived | `archiveOutcome()` | status === 'active' |
| archived | active | `restoreOutcome()` | status === 'archived' |

### Invalid Transitions (throw `OutcomeTransitionError`)

| From | To | Reason |
|------|----|--------|
| active | active | Already active — not archived |
| archived | archived | Already archived — duplicate operation |
| \* | archived | Any non-active status |
| \* | active | Any non-archived status |

## 3. Immutability

### Immutable (from P0.6.5.1)

Once an Outcome is created, these payload fields **MUST NEVER** be modified:

- `outcomeType` — classification of observed outcome
- `targetType` — entity type measured
- `targetId` — entity ID measured
- `metrics` — observed numerical values
- `qualitativeFeedback` — qualitative observations
- `summary` — human-readable summary
- `expectedOutcome` — what was expected
- `observedAt` — when this was observed
- `attribution` — links to decisions/content/drafts

### Mutable (this Service)

Only these lifecycle fields may change during archive/restore:

- `status` — transitions between `'active'` and `'archived'`
- `version` — incremented by OCC on each update
- `updatedAt` — timestamp of last modification

### Guarantee

The Service implementation creates a **defensive copy** of `payload` during transitions:

```typescript
payload: { ...record.payload },
```

This ensures callers cannot mutate the original payload through the returned record.

## 4. Authorization

All lifecycle operations require `authenticatedOwnerId`:

```
archiveOutcome(outcomeId, authenticatedOwnerId, expectedVersion)
restoreOutcome(outcomeId, authenticatedOwnerId, expectedVersion)
importOutcomes(outcomes, authenticatedOwnerId)
```

### Security Model

1. `getById(id, ownerId)` — returns `null` for both non-existent records AND cross-owner lookups (no information leak)
2. `update(record, authenticatedOwnerId, expectedVersion)` — existing OCC mechanism verifies ownership at DB level
3. Type guard ensures only `type === 'outcome'` records are archived/restored

### Owner Boundary in Batch Import

Import requires:
1. `ownerId` must be present (not null, not undefined, not empty)
2. `ownerId` must equal `authenticatedOwnerId`
3. Service never rewrites a missing or mismatched `ownerId`

If `outcome.ownerId` is missing or `!== authenticatedOwnerId`, the import is **rejected** with an explicit error message. The Service does NOT silently replace `ownerId`.

The Service is an **identity verifier**, not an **identity guesser** — it never infers or fills in caller identity.

---

## 5. OCC (Optimistic Concurrency Control)

All lifecycle transitions use **version-based OCC**:

```typescript
await service.archiveOutcome(outcome.id, authenticatedOwnerId, expectedVersion);
```

Flow:
1. Fetch record via `getById()` — includes owner check
2. Validate type and current status
3. Build updated record with `version: expectedVersion + 1`
4. Call `store.update(record, authenticatedOwnerId, expectedVersion)`
5. PrismaMemoryStore's `updateMany` with `WHERE version = expectedVersion` detects conflicts
6. If conflict: throw `MemoryConcurrencyError(record.id, expectedVersion, actualVersion)`

### Why OCC matters

Prevents lost updates when two processes attempt concurrent transitions:

```
Process A: read outcome (version=1) → archive (expectedVersion=1) → version=2
Process B: read outcome (version=1) → archive (expectedVersion=1) → REJECTED (version mismatch)
```

## 6. Batch Import

### Design Decision: Sequential Persistence

This phase uses **validated sequential import**, NOT full transaction atomicity.

```
validate entire batch first
        ↓
persist items sequentially
```

**Rationale:**
- MemoryStore `create()` is already atomic per-record
- Full transaction support would require modifying the PrismaMemoryStore interface (out of scope)
- Documentation explicitly declares partial success is possible

### Two-Phase Import

**Phase 1 — Validation:**
- Owner integrity check (`outcome.ownerId === authenticatedOwnerId`)
- Type check (`outcome.type === 'outcome'`)
- Payload validation (`validateOutcomePayload()`)
- Base record validation (`validateMemoryRecord()`)

**Phase 2 — Persistence:**
- Sequential `store.create()` for each valid item
- Results index-aligned with input array
- Partial success captured in `OutcomeImportResult`

### Import Result

```typescript
interface OutcomeImportResult {
  total: number;           // input length
  imported: number;        // successfully persisted
  failed: number;          // validation + persistence failures
  results: OutcomeImportItemResult[];  // per-item, index-aligned
}
```

### Constraint: No Overwrite

If a record with the same ID already exists, `store.create()` throws (existing Persistency conflict mechanism). Import NEVER overwrites, updates, or deletes existing outcomes.

## 7. Retrieval Interaction

By default, `retrieveOutcomeMemories()`, `getOutcomeHistory()`, and `getLatestOutcome()` use:

```typescript
includeArchived: false  // default
```

### Behavior

| Status | `includeArchived=false` | `includeArchived=true` |
|--------|------------------------|------------------------|
| active | ✅ visible | ✅ visible |
| archived | ❌ hidden | ✅ visible |

### For developers

Archive an outcome when it should no longer influence Decision Content Assembly. The data REMAINS in the database for historical analysis — it's simply excluded from default retrieval contexts.

## 8. API Reference

### OutcomeMemoryService

```typescript
interface OutcomeMemoryService {
  archiveOutcome(
    outcomeId: string,
    authenticatedOwnerId: string,
    expectedVersion: number,
  ): Promise<OutcomeMemory>;

  restoreOutcome(
    outcomeId: string,
    authenticatedOwnerId: string,
    expectedVersion: number,
  ): Promise<OutcomeMemory>;

  importOutcomes(
    outcomes: OutcomeMemory[],
    authenticatedOwnerId: string,
  ): Promise<OutcomeImportResult>;
}
```

### OutcomeTransitionError

```typescript
class OutcomeTransitionError extends Error {
  outcomeId: string;    // The outcome that failed
  fromStatus: string;   // Current status in DB
  toStatus: string;     // Requested transition target
}
```

### Implementation

```typescript
class OutcomeMemoryServiceImpl implements OutcomeMemoryService {
  constructor(store: MemoryStore);  // inject store for testability
}
```

## 9. Error Types

| Error | When thrown |
|-------|------------|
| `MemoryNotFoundError` | Outcome doesn't exist or wrong owner |
| `OutcomeTransitionError` | Invalid state transition or wrong type |
| `MemoryConcurrencyError` | Version mismatch (stale expectedVersion) |
| `MemoryAuthorizationError` | Owner mismatch in update (via store) |
